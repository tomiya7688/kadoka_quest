# 野生個体AI割当（Issue #146）

## 今回の範囲

出現時に `random` / `chase` / `idle` のいずれかを抽選し、野生個体の `ai` に保持する。同じ種族でも個体ごとに異なるAIを持てる。更新・移動では再抽選せず、マップ再入場などで個体を再生成したときだけ抽選する。

**この段階では割当のみ。AI別の実際の移動切替は #147。** 既存の視認・追跡・徘徊・占有・遭遇条件は変更しない。固定モブ、仲間の学習AI、戦闘AI、セーブ形式も変更しない。

## JSON契約

`field_ai_weights` は `random` / `chase` / `idle` をキー、0以上の有限数値を値とする相対重み。合計100でなくてもよく、省略したAIの重みは0。次の優先順位で最初の有効な表を丸ごと使い、表同士は合成しない。

1. マップの `spawns[]` 項目の `field_ai_weights`
2. マップ直下の `field_ai_weights`
3. 種族の `species.json` の `field_ai_weights`
4. ゲーム既定値 `{"random": 70, "chase": 25, "idle": 5}`

未指定、空、合計0、負数、非数値、真偽値、非有限値、未知キーを含む表は次の設定へフォールバックする。巨大すぎて浮動小数へ変換できない整数も同様。エディタの入力UI・保存時検証は #39 の後続作業。

種族の初期値はスライム70/25/5、おばけ40/50/10、メタルスライム85/5/10（random/chase/idle）。最終バランスではなくJSONで変更可能な初期値。

## 責務と再現性

- `data/field_data.py` が出現種族の設定を読み、ゲームの個体リセット時に渡す。
- `kadoka_engine/field_ai.py` が設定の選択・重み抽選を担当。I/Oとpygameに依存しない。
- `HiddenEnemyController.reset` が種族抽選後に個体AIを保持する。
- 同じデータと同じ乱数seedなら同じ個体群を再現できる。抽選回数が増えるため、旧版と同じseedによる個体群の完全一致は保証しない。種族の出現weight自体は変更しない。

## 検証

`tests/test_field_ai_assignment.py` で優先順位、不正表のフォールバック、相対重み、seed再現性、同種族の混在、移動後の保持、JSON読込とゲーム接続を確認する。`tests/test_metal_spawn_tables.py` で種族抽選へ従来の出現weightが渡ることも確認する。
