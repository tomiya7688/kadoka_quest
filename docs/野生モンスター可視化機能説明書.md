# 野生モンスター可視化（Issue #145）

最新の #38 方針に合わせ、野生敵を不可視から可視へ変更する。今回の実装単位は描画のみで、個体移動AIの割当・ポップ率・追跡経路分散は後続Issue。

## データと責務

- `HiddenEnemyController.monsters` の既存個体を `FieldSession` 経由で描画する。描画用の別個体一覧や専用保存形式は作らない。
- 種族IDは `spawn.species_id`、位置は既存の `x / y` を使う。
- 出現時の向きは `direction: front`。移動が成功した方向を記録し、静止時は維持する。方向がない旧呼出側の個体は正面表示する。
- `CharacterImageProvider` が種族の `field_sprites` / `field_sprite_path` を解決し、透明余白除去・最近傍拡縮・キャッシュを担当する。元画像は編集しない。
- `ui/field_renderer.py` は位置と向きを読むだけ。描画中に乱数抽選・移動・出現・戦闘判定は行わない。

## 表示

固定モブと同じ48×48の枠へ縦横比を維持して表示する。カメラ位置を反映し、フィールド領域で切り取る。枠が一部だけ画面端にかかる場合も描画し、完全に画面外なら画像取得を省く。

描画順は地形→野生敵→固定モブ→主人公。戦闘開始などでControllerから削除された個体は次の描画で消える。画像欠損時は種族の代替色を使う四角いマーカーと向きの印を表示し、敵が再び不可視になるのを避ける。

## 変更しないもの

移動先、追跡・徘徊の規則、移動周期、乱数消費、出現率、占有判定、主人公の正面で発生する既存の戦闘条件は維持する。野生敵の移動表示は既存の整数座標更新に従い、補間アニメーションは今回追加しない。内部の `HiddenEnemyController` 等の名前も互換性のため維持する。

## 検証

`tests/test_wild_enemy_rendering.py` で複数種族と四方向、実アセット読込、カメラ端の部分表示とクリップ、画像欠損、個体削除、初期向き、移動後の向き、描画時の状態・乱数非変更を検証する。既存の `test_core.py` が移動周期・占有・正面遭遇を、`test_session_renderers.py` が固定モブ・主人公・パーティ欄を保護する。
