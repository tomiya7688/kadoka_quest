# 配布ビルド機能説明書

## 目的

Python版 Kadoka Quest を Windows 向けの自己完結した `onedir` 配布物として生成し、生成された実行ファイル自体を自動検証する。

## 配布物

```text
dist/
├─ KadokaQuest/
│  ├─ KadokaQuest.exe
│  ├─ _internal/
│  ├─ data/
│  ├─ assets/
│  └─ UserData/
└─ KadokaQuestDeveloper/
   ├─ KadokaQuestDeveloper.exe
   ├─ _internal/
   ├─ data/
   ├─ assets/
   └─ UserData/
```

`data/` と `assets/` はゲーム本体が直接利用する編集可能な正規データをそのまま配置する。`UserData/` はユーザー所有データ専用で、CIのテストセーブは配布成果物へ残さない。

## ワンクリックビルド

Windowsではリポジトリルートの次のBATを使用する。

- `build_python.bat`: Player / Developer の両方をビルドしてスモークテスト
- `build_player.bat`: Player版のみ
- `build_developer.bat`: Developer版のみ

PyInstallerが未導入の場合、BATは `requirements-build.txt` の依存を導入してからビルドする。

同じ処理をCLIから実行する場合:

```powershell
python tools/build/build.py --clean --targets all
python tools/build/test_distribution.py --targets all
```

## Player / Developer 境界

Player版は `launcher.py` をエントリーポイントとし、通常ゲームとゲーム内牧場用 `ranch_manager` のみを起動する。各種エディタ、開発用個体生成、外部個体取り込み、開発用模擬戦はPlayerの起動経路へ含めない。

Developer版は `developer_launcher.py` をエントリーポイントとし、`manage`、ブロック・マップ・モンスター各エディタ、データクリエイターを起動できる。

## frozen実行時のパス

PyInstaller実行時は実行ファイルのあるディレクトリをランタイムルートとする。

- ゲームデータ: `<exe-dir>/data/`
- アセット: `<exe-dir>/assets/`
- セーブ等: `<exe-dir>/UserData/`
- 外部個体: `<exe-dir>/UserData/imports/`

ソース実行時は既存の `savedata/` / `imports/` を維持する。

## 配布物スモークテスト

`tools/build/test_distribution.py` はソースコードを直接importして成功扱いにせず、生成済み実行ファイルを外部プロセスとして起動する。

検証対象:

- Playerランチャー
- Playerゲーム本体
- Player牧場管理
- Developerランチャー
- Developer版の各開発ツール
- `data/` / `assets/` の配置
- `UserData/` の初期化と書き込み
- `savedata/` へ誤書き込みしないこと
- 正常終了時のexit code 0

失敗時、windowed exeで例外ダイアログ待ちにならないよう、スモーク実行では `smoke-error.txt` に例外情報を残して非0終了する。

## 完了時の検証方針

通常の小変更ではソーステストのみでもよい。配布・起動・パス・ランタイム・Player/Developer境界へ影響する変更、または重要変更の最終確認では次を行う。

```text
source tests
↓
Windows Player / Developer build
↓
built executable smoke test
```

GitHub Actions の `Windows distribution` workflow でも同じ順序を実行し、成功時に `dist/` を成果物として保存する。
