# Codexコンテキスト運用

## 目的

Codexが毎回ロードする情報を最小化し、必要な仕様だけを必要な作業時に読む。

## 読み込み順

```text
AGENTS.md
  ├─ Issue本文と優先度
  ├─ 該当する評価フィードバック
  ├─ 該当する開発予定の項目
  └─ 必要な形式・機能説明書だけ
```

`docs/開発予定.md`、評価フィードバック、全機能説明書を毎回まとめて読まない。作業対象に関係する節だけを読む。

## 置き場所

- 毎回必要な不変契約: `AGENTS.md`
- JSON形式: `docs/FORMATS.md`
- 実装済み機能: `docs/*機能説明書.md`
- 変更履歴: `docs/ver.md`
- 未実装の方針: `docs/開発予定.md`
- 外部評価: `docs/評価/`

新しい機能の詳細を `AGENTS.md` に追記せず、専用の機能説明書へ保存する。

## 実装Issueの作成

GitHubで実装Issueを作るときは、`.github/ISSUE_TEMPLATE/implementation.yml` の「実装タスク」を使う。必須なのは `目的 / 対象 / 変更しない範囲 / 受け入れ条件 / 検証` のみである。

`関連仕様 / 既存挙動 / 期待挙動 / データ契約 / 移植境界` は、本文だけでは着手点を判断できないときにだけ追加する。議論履歴や調査ログは本文に複写せず、該当Issue・仕様書への参照に留める。
