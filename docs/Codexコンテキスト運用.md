# Codexコンテキスト運用

## 目的

Codexが毎回読むゲーム仕様を必要な範囲へ絞り、実装の正確さと文脈量の削減を両立するための案内です。Codexは開発規約を[開発者向けの入口](開発者向け/README.md)から読み、ゲームの機能説明書と混在させないでください。

## 読み込み順

```text
AGENTS.md
  ├─ 開発者向けの入口と三つの必読規約
  ├─ Issue本文と優先度
  ├─ 該当する評価フィードバック
  ├─ 該当する開発予定の項目
  └─ 必要な形式・機能説明書だけ
```

Codexは `docs/開発予定.md`、評価フィードバック、全機能説明書を毎回まとめて読まず、作業対象に関係する節だけを読んでください。Codexは `AGENTS.override.md` が指定するローカル必読規約も、その指示に従って読んでください。

## 置き場所

- 毎回必要な不変契約: `AGENTS.md`
- 開発者・実装AI向け規約の正本と入口: `docs/開発者向け/`
- Git除外するローカル追加規約: `docs/開発者向け/ローカル専用/`
- JSON形式: `docs/FORMATS.md`
- 実装済み機能: `docs/*機能説明書.md`
- 変更履歴: `docs/ver.md`
- 未実装の方針: `docs/開発予定.md`
- 外部評価: `docs/評価/`

開発者と実装AIは、新しい機能の詳細を `AGENTS.md` に追記せず、専用の機能説明書へ保存してください。開発者と実装AIは、規約の本文を入口やゲーム仕様へ複写せず、開発者向けフォルダの正本へリンクしてください。

## 実装Issueの作成

GitHubで実装Issueを作るときは、`.github/ISSUE_TEMPLATE/implementation.yml` の「実装タスク」を使う。必須なのは `目的 / 対象 / 変更しない範囲 / 受け入れ条件 / 検証` のみである。

`関連仕様 / 既存挙動 / 期待挙動 / データ契約 / 移植境界` は、本文だけでは着手点を判断できないときにだけ追加する。議論履歴や調査ログは本文に複写せず、該当Issue・仕様書への参照に留める。
