# 種族別撃破経験値（Issue #143）

## 目的とデータ

メタルスライムの撃破報酬を通常敵の調整から独立させる。`species.json` の任意オブジェクト `experience_reward` に整数係数を置く。初期値は `base=300 / per_level=35 / squared_divisor=10`。

`EXP = base + Lv × per_level + floor(Lv² / squared_divisor)`

| Lv | EXP |
| --- | --- |
| 10 | 660 |
| 20 | 1040 |
| 30 | 1440 |
| 50 | 2300 |
| 70 | 3240 |
| 100 | 4800 |

係数は種族側に持ち、種族IDの特別扱いや通常敵への倍率を使わない。未指定または不正な係数は通常計算に戻る。式文字列の評価は行わない。

## 集計と既存動作

- 通常敵のみ: 従来の `8 + Σ(Lv × 3)` を維持する。
- 専用式の敵のみ: 個体ごとの専用EXPの合計。通常戦の基礎点8は付けない。
- 混成: 通常敵分（基礎点8は戦闘ごとに1回）と専用EXPを加算する。
- HPが0で、逃走していない敵だけが対象。全員逃走・敗北・スカウト・プレイヤーの逃走・模擬戦は経験値なし。
- 各味方への配分は従来どおり合計EXPをそれぞれ加える。Lv×24のレベルアップ必要量、Lv100上限、まる・かどかの成長処理は変更しない。
- 演出完了後に1回だけ確定する既存Session契約を維持する。

## 責務

`BattleDataLoader` が種族の係数を `Combatant` へ渡し、I/Oを持たない `core/battle_rewards.py` が撃破経験値を集計する。通常の `BattleProgressionService` と旧互換 `KadokaQuest.award_experience` は同じ集計関数を使う。保存は既存MonsterStore経由で行い、個体JSON・AI JSONに係数を複製しない。

## 検証

`tests/test_battle_rewards.py` は指定6レベルと切捨て、通常・混成・複数メタル、通常式からの独立、係数変更、不正値、逃走除外、両経路の保存・二重付与防止・模擬戦禁止・Lv上限を検証する。実際の中盤地域追加（#141）とメタル域の動的Lv（#144）は別作業。
