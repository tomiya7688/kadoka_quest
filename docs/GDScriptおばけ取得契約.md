# GDScript暗号一致後のおばけ取得・保存契約（#225）

## 導線と責務

#224の正規湧き場→7文字暗号入力→`password_matched` をSceneが受け取り、`application/ghost_acquisition.gd` へ委譲する。UI/会話/rendererはファイルを保存しない。`engine/ghost_acquisition.gd` は不足種族選択とstateフラグの純粋な計画だけ。個体/初期AIのplain契約は既存monster_record_contract、個体公開/JSON置換は既存Dataを使用する。

新規プロフィールは先にフィールドのF5で保存する。未保存/破損/未対応形式/復元できない既存stateでは理由を表示し、暗号取得から初期仲間・保存フォルダを勝手に作らない。登録済みの名前付きGodot保存先だけを使い、Pythonの正規savedataへ自動接続しない。

## 不足分と保存

- Python `reacquire_ghosts` と同じ順のmaru→kadoka。所有フォルダを再走査し、同じ種族を1体でも所有していれば追加しない。名前/Lv/＋/装備/取得元/学習済みAIを変更しない。既に複数所有していても削除/統合しない。
- 不足種族は定義とLv1の能力値/習得スキル/補正の読込を全件確認してから作る。新規IDは `monster_<12桁hex>`、Lv1/経験0/＋なし/装備null/`source: ghost_home_password`、名前/初期AIは種族定義由来。Python MonsterStore/default_aiで同じ出力を読める。
- 既存個体/定義の不正を注意として無視して重複生成せず、取得を拒否する。未知の＋IDは既存の補正契約と同じ注意として保持し、自動修正しない。
- `flags`は辞書だけを許可し、`ghost_entrance_open: true` を保存する。新フラグを発明しない。保存済み位置/向き/復活地点/current_party/他フラグ/未知stateキーを保持し、パーティへ自動追加しない。未保存のフィールド位置はこの取得で保存しない。
- 所有数/セーブスロット数に上限を追加しない。取得後は一覧snapshotを再走査し、F6/牧場台帳と次回起動で同じ個体を確認できる。
- 所有状態に関わらず住処の2体は残る。取得処理から配置/会話/時計/徘徊を初期化しない。誤答/取消はサービスを呼ばず保存しない。

個体は固有の一時フォルダ内にmonster.json/ai.jsonを揃えてから公開し、既存個体を上書きしない。フラグが既にtrueならstateを再出力せず、不足個体だけを追加する。2種族の所有と保存内容を再検証してから加入成功を表示する。既存JSONの数値/空白再出力の限界は従来の[FORMATS](FORMATS.md#gdscriptフィールド試作の保存)と同じ。

## 失敗・再試行

暗号画面を開いた時点のstate digestを保持し、作成前/各公開前/フラグ保存前に再読込する。外部state変更は上書きせず、入力し直すよう案内する。Dataのsave_profileも期待digestを再照合し、置換失敗時は以前のstateを保持する。保存後も期待stateと2種族の所有を確認する。

複数ファイル全体はトランザクションではない。1体公開後の2体目失敗、2体公開後のstate置換失敗、外部更新等では、追加済み個体と保存済みフラグの有無をplain結果の `created / flag_saved / partial / stage / error` に返し、「部分保存」と表示する。公開済み個体や以前の保存を削除/巻き戻ししない。再入力は最新の所有フォルダから不足分だけを作り、既に公開したID/AIを再利用する。全体成功/未成功は `ok / complete` で区別する。

digest照合と再走査は、並行writer間の完全な排他や同種族作成の全件原子性を保証しない。検証後〜書込の競合窓は残る。書込成功後に外部変更が観測された場合も成功を偽装しない。

実Windowsの読込可能・置換不可ロックで、2体公開後のstate失敗/一時ファイル清掃/次回フラグ保存を確認する。2体目公開失敗はテスト専用fault注入、公開後の外部更新は専用コピーへの変更である。壊れた種族/能力値/習得/＋、AI/state/flags/所有フォルダは理由付き拒否する。実セーブは使わない。実IME/手動ウィンドウ視認性/配布export、戦闘AI推論/学習/リセット・外部imports取得は未検証または未移植。
