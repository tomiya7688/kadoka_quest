# 追跡経路分散（Issue #148）

## 範囲

複数のchase個体が存在するマップで、追跡中の近傍経路を `ChaseTraffic` に委譲する。既存の初回視認（同じ行/列・視認距離・通行可能な直線）、random/idle、戦闘、セーブ形式は変更しない。単独の通常追跡は従来の直進処理を使う。

## 予約と混雑

- 主人公の隣接マスまでの経路を選択し、次の3マスを次回移動期限まで予約する。期限未到来の個体の予約も次の更新で参照する。
- 移動コスト1に対し、他個体の予約は+2、他個体が直近1280ms以内に通ったマスは+0.4、他個体の現在位置を将来通る経路は+3。
- 自分の予約・履歴では自分を迂回させない。履歴はマスごとの最新通過記録を保持する。
- 実際の次の1マスは、主人公・固定モブ・野生個体の現在位置への進入を必ず禁止する。固定モブと通行不可地形は経路全体で進入禁止。
- 予約・履歴は通行禁止ではない。一本道では共用を許し、先頭が進んで空いたマスへ後続も進む。先頭が塞いでいる場合の待機は従来どおり必要。

経路計画と移動は個体順に処理する。同じ更新内の移動済み位置・予約が後続に反映される。予約の再計画・期限切れ・個体除去・マップ再生成で古い予定を解放する。時計が巻き戻った場合も履歴と目標記憶をリセットする。

## 迂回中の目標

初めて視認したときだけ目標地点を記憶し、最大4秒、元の視認距離+4マス以内で維持する。迂回で直線視界から外れても、この短期記憶があれば追跡を継続する。主人公が記憶した地点から動き、再視認もできない場合や期限を過ぎた場合は徘徊へ戻る。見えない主人公の新しい位置を追跡目標に更新しない。

この拡張は経路分散中のみ。`sees_player` は現在の視認、`chasing_player` は短期記憶を含む追跡モード。`chase_target` / `chase_until`、予約と履歴は実行時だけで、JSONや仲間AIには書き込まない。

## 計算量の制限

始点と目標の矩形に周囲2マスを加えた範囲でA*探索し、1個体につき最大256ノードで打ち切る。毎フレームではなく移動期限の来た個体だけ再計画する。経路がない・上限に達した場合は安全に待機し、次回再評価する。広域の最適経路や、範囲外の遠回りは保証しない。

## 検証

`tests/test_chase_traffic.py` で分岐路の分散、一本道の共有、予約継続と期限切れ、混雑履歴、実コントローラーの追跡完了、視認前追跡の禁止、占有と探索上限を確認する。既存のAI移動テスト・表示・遭遇テストも継続する。性能チェックは `chase-fork-two` と `wild-movement-24` を使用する。実画面での操作確認は別途必要。
