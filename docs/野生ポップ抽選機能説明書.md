# 野生ポップ抽選（Issue #153）

マップ入場時と既存の補充タイミングで、マップJSONの出現設定からフィールドの野生個体を生成する。

## 抽選

1. ボールスライムと未解放requires_flagの候補を除外する。
2. 従来の上限（面積に応じ12〜24枠、生成可能マス数まで）について、各枠1回ずつpop_rateを判定する。
3. 成功した枠で種族の相対weightから抽選する。小数を整数化せず、最大重みでスケーリングして合計のオーバーフローを避ける。
4. min_level〜max_level（両端含む）からLvを抽選する。
5. 出現項目→マップ→種族→既定70/25/5の順で有効なAI重みを選び、random/chase/idleを決める。
6. 用意した生成可能なマスへ配置する。同じ枠の失敗を再試行して満員にすることはない。

pop_rate=0なら0体、100なら生成可能な全枠、未指定は100。50%は各枠の確率で、毎回正確に半数になる指定ではない。0%でも固定モブ・ボス・明示指定されたイベント戦闘は抑止しない。

種族のweightが全0・負数・非有限・不正型なら生成しない。pop_rate不正時も生成しない。選択された候補のLvが不正ならその枠を生成しない。問題の詳細はDataValidatorで検出する。既存のAI表の不正値フォールバックは維持する。

## Lvと互換性

生成した個体のspawnコピーに実行時専用のrolled_levelを保持し、通常域の接触戦闘へそのまま渡す。原本マップJSONや仲間のセーブにこのキーを追加しない。以前の形式でrolled_levelがない個体・直接指定のイベント戦は従来の範囲抽選に戻る。

メタル域は例外。#144のパーティ連動仕様を優先し、rolled_levelを使用せず、遭遇時の先頭4体からLvを再計算する。種族・装備・仲間の成長データは変更しない。

個体を指定しない直接の野生戦開始も、ポップ率と相対重みの共通抽選を使う。接触済みの個体についてポップ率や種族を引き直さない。

## 実装・検証

- `kadoka_engine/wild_spawn.py`: UI/I/Oなしのポップ判定、相対重み、種族/Lv抽選。
- `hidden_enemy_controller.py`: 枠ごとの抽選、AI、個体配置。
- `core/spawn_levels.py`: 通常域の確定Lv引継ぎとメタル域の例外。
- `apps/game.py`: 戦闘への接続。
- `tests/test_wild_spawn_runtime.py`: 0/100%、失敗枠の非再試行、小数/巨大重み、順序、Lv引継ぎ、保存済み設定、継承、旧データの検証。
- 性能チェック `wild-population-24-slots`: 40×36マップ・24枠の生成を計測。毎フレームではなく入場/補充時の処理として上限5ms。既存の移動性能閾値は変更しない。
