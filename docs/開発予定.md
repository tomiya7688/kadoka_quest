# この文書について

kadoka questにて開発予定のものをまとめる
AIは設計を軽く書いても良いが深い設計については各自機能説明書.mdを作成して記入すること
表はmdの表機能を利用し、図はmermaidを使用する
実装が完了したら項目を削除すること
優先度について 緊急性が高いものは優先度が高く書かれる、尚、デフォルトは0とする
変更履歴:docs\ver.md
変更があればこれを記入すること
AI用メモ:AGENTS.md
仕様書:docs\FORMATS.md,AGENTS.md,README.md

共通コーディングルール
1クラスにつき1ファイル
1クラスは1つの責務を持つ
1関数につき1処理
処理系と画面系,データ系の分離
なにかあたらしいものを追加したときには(機能単位)githubへアップロード、git管理する


#　ロジックの整理
各アプリは独立しておりそれぞれがコマンドによって動作を決定する
よってアプリ間の通信はコマンドによって行われる
例えば対戦画面の　画面　計算　学習　推論　データ読み込み　は当然別アプリである
また戦闘時とモンスター編成画面、マップ移動画面はそれぞれ別のアプリであり、それぞれがデータ層、UI層、処理層を持つ

実装状況: 第8段階まで完了。キャラクター画像プロバイダーが方向別パス解決・PNG読込・フィールド透明余白処理・最近傍拡大・キャッシュを所有する。管理ツールのプロセス状態など残る責務の分割は継続する。

# モンスターのバランス調整ツール
モンスターの強さを調整するための開発者ツールです。
同じレベルの現在作成されているモンスター達をレベル別にひたすら戦闘させ勝敗履歴と勝率、ランキング、各モンスターの高すぎると思われるステータス、低すぎると思われるステータス、耐性の推奨される変化などを各モンスターごとに自信付きで推定+改善案を出すものを作成してください
攻撃 判定:高すぎ 推奨値:-100(もちろんレベルごとに違うからここは最終レベルのステータスを基準にして、チューナーで自動的に下のレベルも調整して)

# 評価用にログを出しながら自動的に操作しまくる(ゲーム本体を)ツール

#　ドットエディタに内蔵する自動生成ツール(lang to dotimg)
依存環境が異なる＋起動してると当然重いと思うのでなくても壊れたり動かなくなっったりしないようにすること(つまりほぼ分離する)
モンスターと、マップ、それからブロックそれぞれに対応して欲しい
学習用ツールが必要ならそれも内蔵しよう(ただし、依存環境がなくても壊れないようにする+インストールできるようにする+確認を表示する)

# ゲーム用実行ファイルをビルドできるようにする
現在のrun_game.batは余りにも開発者用ツールなので、プレイヤー用のゲームを作成&現在の開発者側からはいつでも今の仕様でビルド出来るようにしよう
それに伴いゲームのセーブデータ以外の部分からどういった内容をincludeするか(例えばこのマップは使う、このマップは使わない)みたいなのを選択できるようにし、さらにその設定自体をjsonで保存できるように仕様
