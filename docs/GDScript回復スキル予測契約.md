# GDScript単体HP回復スキルの予測契約

## 背景と目的

GDScript版はPython版の戦闘処理を小さな実装単位で移植します。この契約は、MPを消費する単体HP回復の定義を検証し、明示した対象の回復量と術者の残MPを予測します。予測処理は実資源・Session・保存個体・AIを変更しません。実戦への適用、対象の自動選択、画面表示は後続の別単位です。

開発者は[移行実装単位](ワークフロー/GDScript移行実装単位.md)で進捗を確認してください。実装の入口は`gdscript/engine/heal_skill_contract.gd`です。一覧選択と数値変換は既存の純粋契約を共用し、ファイル・乱数源・AI・UIへ依存しません。

## 定義の選択と対応範囲

開発者は`Contract.prepare(document, skill_id)`へ、`schema_version: 1`と`skills`配列を持つ一覧、および空でない文字列IDを渡してください。処理は選択IDの欠落・重複を拒否し、その定義だけを検証します。成功結果の`skill`は原本と独立した辞書です。

対応する正規スキルは`small_heal`（小回復、回復率0.22・消費MP6）と`healy`（ヒアリー、回復率0.1・消費MP5）、および同じ形式のMOD定義です。使用できる定義キーは`id / display_name / description / kind / heal_ratio / mp_cost`だけです。IDと表示名は空でない文字列、説明は省略可能な文字列、`kind`は`heal`に限定します。通常攻撃ID`attack`と防御ID`defend`は拒否します。

`heal_ratio`は省略時0.15で、有限の負値・0・1を超える値もPythonと同じ計算をします。`mp_cost`はPythonの`int`と同じ0方向切捨ての後に正である必要があります。定義の係数・MP消費は有限数値や数値文字列を使用できますが、bool・非有限値・精度範囲超過を拒否します。MP消費の文字列は整数表記に限定し、`"2"`は許可、`"1.9"`は拒否します。

未知の定義キーはfalse・0・空でも拒否します。治療付き`spirit_recover`は`status_cure_chance`を持つため対象外です。そのHP回復だけを実装して治療済みと扱いません。全体回復、MP回復、状態異常治療、復活、別区分のスキルはこの契約では対応しません。

## 数値要求と結果

開発者は`Contract.quote_heal(definition, request)`へ、対応する定義と次の3キーだけを渡してください。`prepare`を省略して直接定義を渡しても、同じ定義検証を行います。

| 要求キー | 意味と条件 |
| --- | --- |
| `current_mp` | 術者の現在MPです。非負の整数値に限定します。 |
| `target_hp` | 対象の現在HPです。0以上かつ最大HP以下の整数値に限定します。 |
| `target_max_hp` | 対象の最大HPです。正の整数値に限定します。 |

資源の文字列・bool・小数部分のある値は補修せず拒否します。小数部分のない数値は整数化します。未知要求は値によらず拒否し、魔力・防御倍率・耐性・揺らぎ・装備・治療確率を受け取りません。入力と必要な演算結果はJSONとの交換で正確な整数を表せる`±9007199254740991`以内に限定し、必要な積が範囲を超える場合は満HPでも拒否します。

MP不足時は`ok: false / reason: insufficient_mp`です。その他の拒否も`ok: false`と具体的な`reason`を返します。成功結果のフィールドは次のとおりです。

| 結果キー | 意味 |
| --- | --- |
| `ok / scope / skill_id` | 成功true・固定区分`heal_skill_quote`・選択IDです。 |
| `heal_amount` | 最低1を適用した、最大HPで制限する前の回復量です。 |
| `healed` | 最大HPまでの空き量で制限した実回復量の予測です。満HPでは0です。 |
| `remaining_hp` | 現在HPへ`healed`を足した予測値です。 |
| `mp_cost / remaining_mp` | 整数化した消費MPと、現在MPから差し引いた予測値です。満HPでもMPを消費する予測です。 |

成功結果と検証済み定義は独立コピーです。対象HP0も数値として扱えますが、予測成功は死亡対象を選択できることや復活の許可を保証しません。術者・対象の生存、味方関係、習得、装備許可、行動権はこの数値要求では検証しません。

## Python正本との計算一致

比較先は`src/kadoka_quest/core/battle.py`の`BattleEngine._take_action`にある`kind == "heal"`分岐です。回復上限量は`max(1, int(対象最大HP × heal_ratio))`、実回復量はその上限量と`対象最大HP − 対象現在HP`の小さい方です。負の回復率や0でも最低1になり、正の小数積は0方向へ切り捨てます。加算前に実回復量を制限するため、精度上限近傍でも加算途中に上限を超えません。

例えば小回復を現在MP10・対象HP900/最大HP1000で使う予測は、回復上限量220・実回復100・残HP1000・残MP4です。回復量は術者の魔力・装備・対象の防御倍率や属性耐性・乱数で変わりません。Python比較テストは選択だけを固定し、実MP支払いとHP回復を呼びます。対象候補は一体に限定し、AI推論や自動対象選択を移植済みと扱いません。

## 開発者の実行方法と未検証範囲

開発者はリポジトリのルートで、使用できるGodotとPythonを指定して次の検証を実行してください。

```powershell
$env:KADOKA_GODOT_EXECUTABLE = '<Godotの実行ファイル>'
$env:PYTHONPATH = 'src'
& '<Pythonの実行ファイル>' -m pytest tests/test_gdscript_heal_skill.py -q
& '<Pythonの実行ファイル>' tools/performance-check/script/check_gdscript_heal_skill.py
```

共用プローブは専用の一時要求JSONだけを読み、正規データ・実セーブへ書き込みません。性能検査は標準20000回・7サンプル・2000回の事前実行で予測1回の中央値を測ります。中央値3000マイクロ秒以内、期待した回復上限量・実回復量・残HP/MP、元入力保持のすべてが成立した場合だけ成功します。Godot起動・読込・実資源更新・描画・AI・保存の性能は測りません。

Godot未指定時のテストスキップや性能検査の終了コード2は未検証です。開発者はGodotを指定して再実行してください。解析・実行診断、数値不一致、時間超過は失敗です。拒否時は理由と入力を確認し、原本や保存データを自動補修しないでください。
