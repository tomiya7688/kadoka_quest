# 1作業単位のワークフロー

## 背景と目的

Kadoka Questは、利用者・Codex・Claude Code・GitHub Copilot・ChatGPTが同じリポジトリを並行して変更します。各作業者がリモートの最新状態と他者の進行中ブランチを確認しないと、同じ移行単位の二重実装や、古いmainを基にした競合が起きます。

この手順は、実装AIと開発者が1つのIssueまたは1つの独立した小作業を完了するまでの内容です。次の作業では、この手順を最初からやり直してください。

開発者と実装AIは、作業前に[開発規約の入口](../開発者向け/README.md)から三つの必読規約を確認してください。作業手順の本文は本書、コーディング・責務分離・コメントの本文は各規約を正本とします。

## 共有ルールの置き場所

共有ルールの正本は、リポジトリ直下の[AGENTS.md](../../AGENTS.md)・[開発規約の入口](../開発者向け/README.md)・本書です。実装AIごとの入口は、正本へ案内するだけの短い文書にしてください。

| 実装AI | 自動で読む入口 | 入口の役割 |
| --- | --- | --- |
| Codex | `AGENTS.md`、ローカル専用の`AGENTS.override.md`、`.agents/skills/` | AGENTS.mdが正本です。共有スキルは本書の手順を呼び出すだけです。 |
| Claude Code | `CLAUDE.md`、`.claude/skills/` | CLAUDE.mdはAGENTS.mdを読み込むだけです。共有スキルは`.agents/skills/`と同じ内容です。 |
| GitHub Copilot | `.github/copilot-instructions.md` | AGENTS.mdと本書へ案内するだけです。 |
| ChatGPT | 自動で読む入口はありません | 利用者は、作業依頼にAGENTS.mdと本書を読むよう明記してください。 |

開発者と実装AIは、入口文書や共有スキルへ規約本文を複写しないでください。`tests/test_agent_shared_rules.py`は、各入口がAGENTS.mdへ案内していることと、二つの共有スキルの内容が一致することを検査します。

## 実装AIと開発者の手順

1. 作業ツリーと現在ブランチを確認してください。未コミット変更は混在させず、必要なら復元可能なstashへ退避してください。他者の未コミット変更は、退避・上書き・コミットしないでください。
2. `python tools/remote-context/script/sync_remote_context.py` を実行してください。このスクリプトは、リモートの全ブランチを取得し、mainとの差分と、mainへ未統合で最近14日以内に更新されたリモートブランチの一覧を表示します。差分と競合対象を確認し、現在の作業ブランチへ安全に取り込んでから作業を始めてください。競合時はユーザーの未コミット変更を優先して保持し、取り込み結果をテストしてください。
3. GitHub Issuesを確認し、[Issue優先度方針](Issue優先度方針.md)に従って未対応Issueを選んでください。現在は[GDScript移行単位](GDScript移行実装単位.md)をP1内で優先し、実装済みの単位は再実装しないでください。関連するフィードバック・開発予定・CODEMAPだけを読んでください。
4. 手順2の進行中ブランチ一覧と公開中のPRに、選んだ単位と同じ作業がないか確認してください。同じ作業がある場合は、その単位へ着手せず、次の独立した単位を選ぶか利用者へ確認してください。
5. mainの最新から作業ブランチを作ってください。ブランチ名には、作業者が分かる接頭辞を付けてください。例は`codex/`・`claude/`・`copilot/`・利用者の`kadoka/`です。既存のユーザー変更、保存データ、無関係な未追跡ファイルは変更しないでください。
6. 選んだIssueの受け入れ条件を満たす最小の変更を実装してください。
7. 関連テスト、ヘッドレス全テスト、構文検査、`git diff --check` を実行してください。
8. 仕様書・`docs/ver.md`・必要なテストを更新してください。Issue本文、CODEMAP、形式仕様は必要な場合だけ更新してください。`docs/ver.md`の番号は、手順9の再取得後に最新の番号と重ならないか確認してください。
9. コミットの直前に、手順2のスクリプトをもう一度実行してください。作業中にmainが進んでいた場合は、mainを取り込み、関連テストを再実行してください。
10. 対象ファイルだけをコミットしてください。push、PR作成、Issue完了、保存データ変更は明示的な指示がある場合だけ行ってください。pushする直前にもリモートを再取得してください。
11. PRがmainへマージされたら、[GDScript移行単位](GDScript移行実装単位.md)の状態を「main反映済み（PR番号）」へ更新してください。
12. 実装内容、検証結果、コミット、未実行の外部操作、未検証の範囲を報告して1作業を終えてください。

## 評価チーム

1. 該当機能を確認する。
2. 再現条件・期待結果・優先度を含むIssueを作成する。
