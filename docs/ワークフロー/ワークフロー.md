# 1作業単位のワークフロー

この手順は、Codexが1つのIssueまたは1つの独立した小作業を完了するまでの内容である。次の作業は、この手順を最初からやり直す。

## Codex

1. 作業ツリーと現在ブランチを確認する。未コミット変更は混在させず、必要なら復元可能なstashへ退避する。
2. `git fetch origin --prune` でリモート変更を取得する。差分と競合対象を確認し、現在の作業ブランチへ安全にマージしてから作業を始める。競合時はユーザーの未コミット変更を優先して保持し、取り込み結果をテストする。
3. GitHub Issuesを確認し、[Issue優先度方針](Issue優先度方針.md)に従って未対応Issueを選ぶ。P0は緊急対応専用、通常はP1から順に扱う。現在は[GDScript移行単位](GDScript移行実装単位.md)をP1内で優先し、ローカル実装済みは再実装しない。関連するフィードバック・開発予定・CODEMAPだけを読む。
4. Issueごとに作業ブランチを作る。既存のユーザー変更、保存データ、無関係な未追跡ファイルは変更しない。
5. 選んだIssueの受け入れ条件を満たす最小の変更を実装する。
6. 関連テスト、ヘッドレス全テスト、構文検査、`git diff --check` を実行する。
7. 仕様書・`docs/ver.md`・必要なテストを更新する。Issue本文、CODEMAP、形式仕様は必要な場合だけ更新する。
8. 対象ファイルだけをコミットする。push、PR作成、Issue完了、保存データ変更は明示的な指示がある場合だけ行う。
9. 実装内容、検証結果、コミット、未実行の外部操作を報告して1作業を終える。

## 評価チーム

1. 該当機能を確認する。
2. 再現条件・期待結果・優先度を含むIssueを作成する。
