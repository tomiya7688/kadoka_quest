# GDScript移行の実装単位

現在の最優先の開発方針はGDScript版への移行。通常の移行作業は `gdscript` と `priority: p1` を付け、同じP1の他作業より先に扱う。P0は待たせられない緊急障害の復旧だけに残す。移行完了またはユーザーの方針変更時に、この優先枠を見直す。

既存のマップ/移動/位置保存、初期個体・一覧、現在編成、プリセットはローカル実装済み。#10/#111はディレクトリの境界であり、GDScript本体の全機能移植を追うIssueではない。未移植機能は以下の小単位で進める。

MP付き単体物理スキルの[定義・数値予測契約](../GDScript物理スキル予測契約.md)をローカル実装した（未push、検証はver#92）。通常攻撃と数値だけを共用し、MP不足と未対応効果を拒否する。予測であり、実MP消費やSessionへの行動適用ではない。

MP付き単体物理スキルの予測を[物理行動契約](../GDScript物理スキル行動契約.md)へ接続しました（未push、検証はver#93）。物理行動は、開始時にコピーした正規定義・習得・許可装備とID索引を使い、Sessionの最新の行動票と資源を検証して一回分の行動権取得・MP支払い・HP適用・行動終了を実行します。MP不足・未習得・未対応効果では、提示中の行動票と資源を保持します。物理スキルIDを通常攻撃IDへ置き換えて専用APIを呼ぶ処理は行いません。

[MP付き単体魔法の予測契約](../GDScript魔法スキル予測契約.md)はローカル実装済みです（未push、検証はver#95）。定義の一意性・MP不足・未対応効果を検証し、HP/MPを変更せず、通常ダメージ・無効・吸収と残MPを予測します。魔法には物理防御倍率を適用しません。自傷・状態異常・全体攻撃等は、効果を省略して成功とせず拒否します。

[単体魔法の実行準備とSessionへの行動適用](../GDScript魔法スキル行動契約.md)をローカル実装しました（未push、検証はver#96）。準備処理は正規習得・許可装備・種族と装備の属性耐性を再構築し、行動処理は最新の予約とHP/MPを検証して実MP消費・ダメージまたは吸収回復・終了処理を実行します。基本ぼうぎょは魔法を軽減しません。不足・不正・未対応効果では予約と資源を保持します。AIと戦闘画面は未接続で、全スキル移植の完了ではありません。

[自傷付き単体魔法metal_burstの定義・数値予測](../GDScript自傷魔法予測契約.md)をローカル実装しました（未push、検証はver#97）。対象への通常・無効・吸収を通常魔法と共用し、その後の最大HP基準の代償と術者HP1の下限をPython正本に合わせます。計算上の代償量と実HP減少を区別し、入力と保存形式は変更しません。

[自傷付き単体魔法のSessionへの実適用](../GDScript自傷魔法行動契約.md)をローカル実装しました（未push、検証はver#98）。通常魔法と共用の行動処理を構築時に自傷専用へ固定し、専用入口から最新予約・習得・敵対象・現在資源を検証して単一claim→実MP消費→対象効果→術者の実HP代償→finishを実行します。無効・吸収・最後の敵の撃破でも代償を適用し、HP1を残します。不正・不足・取消・重複は追加消費しません。通常魔法の入口は引き続き自傷定義を拒否します。

[吸MPスキルpossessの定義・数値予測](../GDScript吸MPスキル予測契約.md)をローカル実装しました（未push、検証はver#99）。敵HP効果を通常魔法と共用し、MP消費後の敵MP喪失と術者最大MPまでの回復を分離します。敵HP0でも吸収を予測し、無効/吸収耐性では吸収しません。入力と保存形式は変更せず、未知効果/要求や不正MPを拒否します。

[吸MPスキルのSessionへの実適用](../GDScript吸MPスキル行動契約.md)をローカル実装しました（未push、検証はver#100）。吸MP専用入口は最新予約・習得・許可装備・敵対象・現在資源を検証し、単一claim→MP消費→敵HP効果→敵MP喪失/術者MP回復→finishを実行します。敵撃破後もMPを奪い、術者の最大MPで回復を制限します。不正・不足・取消・重複では追加消費せず、通常魔法・自傷入口は吸MP定義を拒否します。

[MP付き単体HP回復スキルの定義・数値予測](../GDScript回復スキル予測契約.md)をローカル実装しました（未push、検証はver#101）。small_heal/healyと互換MOD定義の回復上限量・最大HPで止まる実回復量・消費後MPを、入力変更なしで予測します。治療付きspirit_recover・未知効果/要求・不正資源やMP不足は拒否し、対象HP0の数値予測は復活許可を意味しません。

[MP付き単体HP回復のSession実適用](../GDScript回復スキル行動契約.md)をローカル実装しました（未push、検証はver#102）。最新予約・習得・許可装備・生存する同陣営対象と現在資源を検証し、単一claim→MP消費→上限付きHP回復→finishを実行します。本人回復と満HPでのMP消費に対応し、不正・不足は予約と資源を保持します。治療・AI・画面は未接続です。

[状態異常一つの治療予測](../GDScript状態治療予測契約.md)をローカル実装しました（未push、検証はver#103）。解除不可を飛ばした最初の候補一件を、有限確率と明示判定値で予測し、原本と独立した残存一覧を返します。候補なしは判定不要、候補があれば確率0でも判定値を要求します。未知IDとJSON互換の拡張情報を保持しますが、付与/継続効果を実装済みとは扱いません。既存HP回復APIの治療付き定義拒否は維持します。

[治療付きHP回復の純粋スキル契約](../GDScript治療付き回復予測契約.md)をローカル実装しました（未push、検証はver#104）。spirit_recoverの回復上限・実回復量・消費後MPと一件治療を既存純粋契約へ委譲します。MP不足は治療一覧/判定値の検証前に拒否し、不正では部分成功を返しません。満HPでもMP消費と治療を予測し、入力・実資源・保存形式は変更しません。純粋予測は専用の治療付き回復行動へ接続しました。AI・画面は未接続です。

[戦闘状態一覧の独立保持・一件治療](../GDScript戦闘状態一覧契約.md)をローカル実装しました（未push、検証はver#105）。状態所有者は一度だけ初期化し、予測で一覧を変更せず、実適用時の最新一覧から成立した候補一件だけを除きます。外部一覧/古い予測の持ち込みを拒否し、数値snapshot六キーと保存形式は変更しません。状態所有者はHP/MPや行動予約を扱いません。最新一覧の付与も専用入口へ接続し、Sessionは治療/付与を予約付きで制限します。継続効果・AI・画面は未接続です。

[治療付き回復の実行準備](../GDScript治療付き回復準備契約.md)をローカル実装しました（未push、検証はver#106）。開始資源・習得・許可装備を既存HP回復と共用検証し、全参加者に一致する明示初期状態を独立コピーします。専用入口で正規定義を選び、通常HP回復の治療拒否は維持します。返却初期状態は通常データであり、Session保持やHP/MP/状態の実更新ではありません。

[Sessionへの初期状態保持と独立読取](../GDScript戦闘Session状態保持契約.md)をローカル実装しました（未push、検証はver#107）。専用start_with_statusesは全員の数値資源と明示初期状態が成功した場合だけ保持し、statuses/statusは独立コピーを返します。従来入口・数値snapshot・保存形式は維持します。ラウンド/死亡/逃走/防御解除は状態を暗黙解除しません。Applicationの専用開始と実治療行動は後続単位で接続しました。Session予約付き付与は独立入口へ接続し、AI・画面は未接続です。

[治療付きHP回復の実適用](../GDScript治療付き回復行動契約.md)をローカル実装しました（未push、検証はver#108）。構築時に固定した専用区分で最新予約/習得/HPMP/状態を検証し、単一claim→MP消費→回復→一件治療→finishを同期実行します。Applicationの専用開始は全成功時だけ参照を切り替えます。通常入口は治療を拒否し、数値/保存形式を維持します。同じ予約の治療再判定は不成立/候補なしでも拒否します。AI/画面は未接続です。

[状態一件の純粋付与予測](../GDScript状態付与予測契約.md)をローカル実装しました（未push、検証はver#109）。付与予測は同IDを重ねず、耐性補正と明示判定から独立一覧を返します。現在一覧の形式検査を治療と共用し、原本と保存形式は変更しません。実更新は個体/参加者集合/Session予約の専用入口へ接続しました。付与付き攻撃行動・継続効果・AI・画面は未接続です。

[状態所有者への一件付与](../GDScript戦闘状態一覧契約.md#最新一覧への一件付与)をローカル実装しました（未push、検証はver#110）。状態所有者は最新一覧で準備/予測/実付与を行い、成功候補だけを独立コピーして追加します。同IDを重ねず、古い一覧/予測による上書きを拒否します。治療後の再付与と返却値の編集からの保護を検証します。数値/保存形式は変更せず、Sessionの予約付き付与は専用入口へ接続しました。付与付き攻撃行動・継続効果・AI・画面は未接続です。

[参加者状態集合の一件付与](../GDScript参加者状態付与契約.md)をローカル実装しました（未push、検証はver#111）。状態集合はside/idで対象を確認し、最新一覧の準備/予測/実付与を個体所有者へ委譲します。同IDの別陣営や他の七体は変更せず、外部一覧/古い予測を拒否します。数値/保存形式は維持し、Session予約の付与は専用入口へ接続しました。付与付き攻撃行動・継続効果・AI・画面は未接続です。

[Session予約付き一回付与](../GDScript予約付き状態付与契約.md)をローカル実装しました（未push、検証はver#112）。Sessionは現在取得済み予約/最新生存を確認し、正常不成立/重複も一回判定として再抽選を防ぎます。不正条件は予約/数値/状態を保持して再試行できます。治療と付与の各一回記録を内部所有者へ分離し、数値/保存形式は維持しました。

次の候補は、状態付与付き単体攻撃の純粋準備/予測と、正規定義・MOD定義の対応範囲の確認です。スキル/攻撃行動接続・耐性再構築・継続効果・AI・画面は独立して扱います。魔法/自傷/吸MP/回復/治療/付与の各予測・行動と状態保持、次候補は未起票のローカル単位です。公開Issueの状態変更や起票は明示的な指示がある場合だけ行います。

## 進め方

1. リモート取得と作業ツリー確認後、P0の緊急性を確認する。通常はP1のgdscript単位から依存順に1件選ぶ。
2. `start_task.bat` の候補がローカル実装済みなら再実装せず、この表・コミット・Issueの進捗を確認して次の未対応単位へ進む。
3. 未移植機能を代替の成功処理で埋めず、純粋engine / data I/O / application調停 / UIを分ける。既存JSONを直接使い、実セーブを検証に使わない。
4. 実GodotとPython正本の比較、関連/全テストと更新履歴を残す。手動画面・export未検証は区別する。
5. ローカル実装済みとGitHubにコード反映済みを区別する。未pushの間はIssueを閉じず、ローカルコミットと検証範囲を記録する。push/PR/完了操作は明示的な指示に従う。
