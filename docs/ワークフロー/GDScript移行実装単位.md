# GDScript移行の実装単位

現在の最優先の開発方針はGDScript版への移行。通常の移行作業は `gdscript` と `priority: p1` を付け、同じP1の他作業より先に扱う。P0は待たせられない緊急障害の復旧だけに残す。移行完了またはユーザーの方針変更時に、この優先枠を見直す。

既存のマップ/移動/位置保存、初期個体・一覧、現在編成、プリセットはローカル実装済み。#10/#111はディレクトリの境界であり、GDScript本体の全機能移植を追うIssueではない。未移植機能は以下の小単位で進める。

MP付き単体物理スキルの[定義・数値予測契約](../GDScript物理スキル予測契約.md)をローカル実装した（未push、検証はver#92）。通常攻撃と数値だけを共用し、MP不足と未対応効果を拒否する。予測であり、実MP消費やSessionへの行動適用ではない。

MP付き単体物理スキルの予測を[物理行動契約](../GDScript物理スキル行動契約.md)へ接続しました（未push、検証はver#93）。物理行動は、開始時にコピーした正規定義・習得・許可装備とID索引を使い、Sessionの最新の行動票と資源を検証して一回分の行動権取得・MP支払い・HP適用・行動終了を実行します。MP不足・未習得・未対応効果では、提示中の行動票と資源を保持します。物理スキルIDを通常攻撃IDへ置き換えて専用APIを呼ぶ処理は行いません。

[MP付き単体魔法の予測契約](../GDScript魔法スキル予測契約.md)はローカル実装済みです（未push、検証はver#95）。定義の一意性・MP不足・未対応効果を検証し、HP/MPを変更せず、通常ダメージ・無効・吸収と残MPを予測します。魔法には物理防御倍率を適用しません。自傷・状態異常・全体攻撃等は、効果を省略して成功とせず拒否します。

[単体魔法の実行準備とSessionへの行動適用](../GDScript魔法スキル行動契約.md)をローカル実装しました（未push、検証はver#96）。準備処理は正規習得・許可装備・種族と装備の属性耐性を再構築し、行動処理は最新の予約とHP/MPを検証して実MP消費・ダメージまたは吸収回復・終了処理を実行します。基本ぼうぎょは魔法を軽減しません。不足・不正・未対応効果では予約と資源を保持します。AIと戦闘画面は未接続で、全スキル移植の完了ではありません。

[自傷付き単体魔法metal_burstの定義・数値予測](../GDScript自傷魔法予測契約.md)をローカル実装しました（未push、検証はver#97）。対象への通常・無効・吸収を通常魔法と共用し、その後の最大HP基準の代償と術者HP1の下限をPython正本に合わせます。計算上の代償量と実HP減少を区別し、入力と保存形式は変更しません。

[自傷付き単体魔法のSessionへの実適用](../GDScript自傷魔法行動契約.md)をローカル実装しました（未push、検証はver#98）。通常魔法と共用の行動処理を構築時に自傷専用へ固定し、専用入口から最新予約・習得・敵対象・現在資源を検証して単一claim→実MP消費→対象効果→術者の実HP代償→finishを実行します。無効・吸収・最後の敵の撃破でも代償を適用し、HP1を残します。不正・不足・取消・重複は追加消費しません。通常魔法の入口は引き続き自傷定義を拒否します。

[吸MPスキルpossessの定義・数値予測](../GDScript吸MPスキル予測契約.md)をローカル実装しました（未push、検証はver#99）。敵HP効果を通常魔法と共用し、MP消費後の敵MP喪失と術者最大MPまでの回復を分離します。敵HP0でも吸収を予測し、無効/吸収耐性では吸収しません。入力と保存形式は変更せず、未知効果/要求や不正MPを拒否します。

[吸MPスキルのSessionへの実適用](../GDScript吸MPスキル行動契約.md)をローカル実装しました（未push、検証はver#100）。吸MP専用入口は最新予約・習得・許可装備・敵対象・現在資源を検証し、単一claim→MP消費→敵HP効果→敵MP喪失/術者MP回復→finishを実行します。敵撃破後もMPを奪い、術者の最大MPで回復を制限します。不正・不足・取消・重複では追加消費せず、通常魔法・自傷入口は吸MP定義を拒否します。

[MP付き単体HP回復スキルの定義・数値予測](../GDScript回復スキル予測契約.md)をローカル実装しました（未push、検証はver#101）。small_heal/healyと互換MOD定義の回復上限量・最大HPで止まる実回復量・消費後MPを、入力変更なしで予測します。治療付きspirit_recover・未知効果/要求・不正資源やMP不足は拒否し、対象HP0の数値予測は復活許可を意味しません。

## 進め方

1. リモート取得と作業ツリー確認後、P0の緊急性を確認する。通常はP1のgdscript単位から依存順に1件選ぶ。
2. `start_task.bat` の候補がローカル実装済みなら再実装せず、この表・コミット・Issueの進捗を確認して次の未対応単位へ進む。
3. 未移植機能を代替の成功処理で埋めず、純粋engine / data I/O / application調停 / UIを分ける。既存JSONを直接使い、実セーブを検証に使わない。
4. 実GodotとPython正本の比較、関連/全テストと更新履歴を残す。手動画面・export未検証は区別する。
5. ローカル実装済みとGitHubにコード反映済みを区別する。未pushの間はIssueを閉じず、ローカルコミットと検証範囲を記録する。push/PR/完了操作は明示的な指示に従う。
