# 野生接触から戦闘・復帰（Issue #149）

## 接触

主人公が野生個体のマスへ移動しようとしたとき、または個体が主人公の正面1マスに来たときに戦闘を始める。主人公が1マス移動した先の正面にいる個体も対象。側面・背面・斜めの隣接だけでは開始しない。キャラクター同士を重ねて接触判定する方式ではない。

`check_hidden_collision` と `start_wild_battle` は、実際に開始した場合だけTrueを返す。フィールド以外の画面、既存戦闘あり、仲間なしでは開始しない。同じ判定が繰り返されても進行中の戦闘を置き換えない。

## 対象の引き継ぎ

接触した個体が持つ `spawn` の種族とレベル情報を戦闘生成へ渡す。種族を出現表から引き直すことはない。#153以降、通常域は生成時の `rolled_level` を引き継ぐ（旧個体で未指定なら接触時に範囲抽選）。メタル域は引き続き #144 の遭遇時パーティ連動範囲を使用する。

フィールド移動AI・経路記憶・予約は戦闘AIに転用しない。戦闘AIは種族の戦闘プロファイルから生成する。

個体生成・BattleEngine生成・BattleSession開始が成功した後で、接触した野生個体をフィールドから除去し、経路予約を解放する。それ以前の生成例外では個体を残し、例外は呼出元へ伝える。MODの壊れたデータ自体を自動修復・黙殺する機能ではない。

## 戦闘中と復帰

- 戦闘中はフィールド個体を更新しない。
- 正規の `RuntimeOrchestrator → BattleCommandApplication → BattleFlowService` でコマンド・ログ再生・終了処理を実行する。
- AI保存・経験値などの終了処理はログ再生完了後に一度だけ実行する。
- 勝利、プレイヤー逃走、スカウト、敵全員逃走では元のフィールドへ戻る。接触済み個体は復元しない。
- 敗北では登録した教会へ復活する。元の地点で再開しない。
- 残りの野生個体が3体以上なら、それらの状態と位置を保つ。3体未満で出現表がある場合は、従来どおり個体群を再生成する。再生成は消費済みオブジェクトの再利用ではない。
- 固定モブの勝利時消滅、模擬戦、セーブ形式は今回変更しない。

## 検証範囲

`tests/test_wild_encounter_flow.py` は一時セーブで実ゲームを構築し、4種類の接触経路、種族とLv、開始拒否、生成失敗、二重開始、戦闘中の停止、5種類の終了結果、ログ再生・保存・復帰までを確認する。終了結果のテストではHPや乱数を制御して終局条件を作り、戦闘・進行・保存の実装は実物を使う。手動プレイや画面の見た目を検証したものではない。
