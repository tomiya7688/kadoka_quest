# メタルエリアの動的Lv（Issue #144）

## 設定と適用時点

マップJSON直下の `encounter_context` を `metal_area` にする。野生戦の敵個体を作る `KadokaQuest.make_wild` が、現在のパーティを純粋計算 `core/spawn_levels.py` へ渡し、返された範囲を乱数抽選へ使う。

裏で歩く敵は出現項目だけを持ち、Lvは遭遇時に決まる。編成や仲間Lvが変われば次の遭遇で再計算する。計算結果はマップJSONや仲間の個体JSONへ書き戻さない。生成された敵個体には通常どおり確定Lvを持たせ、既存の能力・スキル・逃走・経験値処理がその個体を使う。

## 計算

1. 戦闘エンジンと同じ先頭4体だけを対象にする。控えや牧場の所有個体は使わない。
2. `kadoka / maru` の換算Lvは `max(1, 実Lv - 10)`、それ以外は実Lv。通常おばけは減算しない。
3. 換算後に高い順へ並べ、原則2位を基準に±3。
4. 1位と2位の差が20以上なら1位を基準に±5。1体編成も1位±5。
5. 最小・最大Lvをそれぞれ1〜100へ丸め、両端を含む範囲から抽選する。

| 編成 | 出現Lv |
| --- | --- |
| 62 / 58 / 43 / 21 | 55〜61 |
| 80 / 65 / 40 / 20 | 62〜68 |
| 100 / 1 / 1 / 1 | 95〜100 |
| 80 / 61（差19） | 58〜64 |
| 80 / 60（差20） | 75〜85 |
| まる80 / 通常60 | 57〜63（換算70 / 60） |
| 通常50のみ | 45〜55 |

空パーティでは既存の戦闘開始ガードにより戦闘を始めず、裏の敵も消費しない。計算関数へ空編成を直接渡した場合は `ValueError` とする。

## 適用範囲と互換性

- `metal_area` の野生戦生成経路で全種族に適用する。同じ経路を使う固定モブ戦にも適用される。
- 通常・省略・未知のコンテキストでは従来の `min_level / max_level` をそのまま使用する。
- メタルエリアでは固定Lv欄を実行時に上書きして使うが、JSONの値は変更しない。既存エディタの検証を通すため1〜100の有効範囲を残す。
- 模擬戦の取込個体、仲間の実Lv・成長速度、通常域の出現率には影響しない。
- 新しい地域や既存マップへの接続は追加しない。#141の中盤地域配置は引き続き別作業。

## 検証

`tests/test_spawn_levels.py` で指定編成、差19/20/21、換算後の順位、上下限、1体・空編成、順序独立性、先頭4枠、編成変更、通常域への復帰、データ非変更を確認する。実際の野生戦生成でLv100のメタルが逃走率60%・撃破4800EXPの個体になることも確認する。
