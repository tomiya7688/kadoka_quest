# 属性・耐性システム設計

## 目的

攻撃属性と状態異常属性を別系統として定義し、耐性レベル名を共通カタログへ固定する。既存JSONの `weak / normal / strong / immune / absorb` を壊さず、将来の `very_weak / resist / reflect` 実装へ拡張できる契約とする。

この文書はデータ契約と解決規則を定めるReview仕様であり、全属性スキル・全状態異常・反射ランタイムを一度に実装するものではない。

## 攻撃属性キー

正式な魔法・属性ダメージキーは次の9種とする。

| 日本語 | key |
|---|---|
| 炎 | `fire` |
| 光 | `light` |
| 雷 | `lightning` |
| 木 | `wood` |
| 闇 | `dark` |
| 土 | `earth` |
| 水 | `water` |
| 氷 | `ice` |
| 風 | `wind` |

既存の `physical` は物理攻撃種別、`mental` は既存MP干渉等の互換キーとして残す。新しい9属性へ無理に置換しない。

skill側は従来どおり `element` にキーを持つ。

```json
{
  "id": "fire_bolt",
  "kind": "magic",
  "element": "fire"
}
```

## 状態異常属性キー

状態異常の付与可否はダメージ倍率と同じ辞書へ混在させず、species側の `status_resistances` で管理する。

| 日本語 | key |
|---|---|
| 毒 | `poison` |
| 麻痺 | `paralysis` |
| 催眠 | `sleep` |
| 混乱 | `confusion` |
| 拘束 | `bind` |
| 呪縛 | `curse_bind` |
| 呪詛 | `curse` |

後続の出血等は新しい状態異常キーとしてこの系統へ追加する。

## 8段階の耐性レベル

耐性レベル名は以下の順序を正式順序とする。

| 順位 | key | 表示 | ダメージ初期意味 |
|---:|---|---|---|
| 0 | `very_weak` | 超弱 | 1.8倍 |
| 1 | `weak` | 弱 | 1.4倍 |
| 2 | `normal` | 通常 | 1.0倍 |
| 3 | `resist` | 耐性 | 0.8倍 |
| 4 | `strong` | 強 | 0.6倍 |
| 5 | `immune` | 無効 | 0ダメージ |
| 6 | `absorb` | 吸収 | 本来受けるダメージ相当をHP回復へ変換 |
| 7 | `reflect` | 反射 | 対象へ与えるはずの効果を攻撃側へ返す |

既存値 `weak=1.4 / normal=1.0 / strong=0.6 / immune=0 / absorb` の意味は維持する。追加3段階だけを後方互換で増やす。

### 一箇所で管理するもの

後続実装では耐性の順序・表示名・ダメージ係数・特殊種別を1つのpureな耐性定義モジュールに置く。`BattleEngine`、装備補正、validatorが独自配列をそれぞれ持たない。

特に現在 `BattleDataLoader` が持つ装備補正用の5段階配列と、`BattleEngine` の倍率辞書は同じ正式定義を参照する形へ移行する。

## species JSON

ダメージ属性は既存 `resistances` を維持する。

```json
{
  "resistances": {
    "fire": "weak",
    "ice": "strong",
    "lightning": "normal"
  },
  "status_resistances": {
    "poison": "strong",
    "paralysis": "immune"
  }
}
```

未指定キーは `normal` として扱う。

### status_resistancesの扱い

状態異常耐性は同じレベル名カタログを参照するが、ダメージ計算へ流さない。

初期の付与率補正は次を基準とする。

- `very_weak`: 基礎付与率 × 1.5（最終100%上限）
- `weak`: × 1.25
- `normal`: × 1.0
- `resist`: × 0.75
- `strong`: × 0.5
- `immune`: 0%

`absorb` と `reflect` は状態異常には使用禁止とする。validatorで検出する。将来「状態異常反射」が必要なら別仕様として明示的に追加し、ダメージ反射を流用しない。

## 吸収

`absorb` は現在の挙動を正式仕様とする。

- 属性攻撃によるHP減少を発生させない。
- 本来の属性ダメージ量を基準にHPを回復する。
- 最大HPを超えない。
- その攻撃に付随するMP吸収や追加効果は、吸収対象へ通常ヒットしたものとして二重適用しない。
- 吸収による回復は「負のダメージ」として内部評価へ返してよいが、画面上では回復として表示する。

## 反射

`reflect` は吸収とは別の特殊解決とする。

- 元対象はHP/MP/状態異常の影響を受けない。
- 反射可能な単体属性攻撃は攻撃者へ1回だけ返す。
- 反射された攻撃をさらに反射しない。無限反射を禁止する。
- 反射先では攻撃者自身の該当属性耐性を適用する。
- 自傷、field効果、純物理通常攻撃を自動的に反射対象へ含めない。
- 全体攻撃では `reflect` を持つ対象分だけ個別に攻撃者へ返し、他対象への通常解決を続ける。

どのskillが反射可能かは後続実装で `reflectable` 等の明示契約を追加してもよい。未指定時の既定は、属性を持つmagic系のみ反射可能とする案を基準にする。

## 装備による耐性段階補正

既存 `resistance_steps` は正式8段階順序を上下する。

- 正数: より耐性が強い方向
- 負数: より弱い方向
- 上下限でclamp

ただし装備の段階補正だけで `absorb` / `reflect` へ到達させるかはゲームバランス上の影響が大きい。後続実装の既定は **通常段階補正の上限を `immune`** とし、`absorb` / `reflect` はspeciesまたは装備の明示値でのみ付与する。現在の装備挙動を変更する際は個別テストを追加する。

## 後方互換

- 既存 `resistances` をそのまま読む。
- 未指定属性は `normal`。
- 現在存在する5レベル名の意味・倍率は変更しない。
- `physical` / `mental` の既存利用を削除しない。
- `status_resistances` が無いspeciesは全状態異常 `normal` とみなす。
- schema_versionをこの設計だけを理由に即時更新しない。追加キーを無視する現行方針を利用する。

## 責務配置

```text
species/skill/equipment JSON
          |
          v
central resistance definition (pure)
      /             \
     v               v
BattleDataLoader   status resolver
     |
     v
BattleEngine damage/special resolution
```

- 正式キー・段階順序・倍率・特殊種別: pygame/file I/Oなしの共通定義。
- `BattleDataLoader`: species + equipmentから最終耐性値を組み立てる。
- `BattleEngine`: ダメージ、immune、absorb、reflectの実戦闘解決。
- 状態異常resolver: `status_resistances` と基礎付与率から付与可否を解決。ダメージ倍率関数は使わない。
- validator: 未知属性、未知レベル、状態異常へのabsorb/reflectを検出。

## 後続実装順

1. 共通耐性定義を追加し、既存5段階をそこへ移す。
2. `very_weak / resist` の倍率処理を追加。
3. `reflect` の単体テストと解決処理を追加。
4. `status_resistances` と状態異常付与resolverを追加。
5. equipment `resistance_steps` を正式順序へ接続。
6. validator / editorへキー選択と検証を追加。
7. 新属性・新状態異常をゲームデータへ段階的に採用。

この順序なら既存戦闘の5段階挙動を維持しながら拡張できる。
