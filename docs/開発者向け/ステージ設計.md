# ステージ・ワールド設計

## 背景

Kadoka Questには、はじまりの街、モンスター牧場、はじまりの森、新緑の森、ロクター村、おばけの住処が既に存在します。

現状は主要ループを試すためのマップとして機能していますが、RPGとして見た場合は「この場所で何を覚えるか」「どこが印象に残るか」「なぜ次の地域へ進むか」がまだ弱く、マップを増やすほど単なる接続されたフィールドになりやすい状態です。

本書では、既存マップと今後追加するマップを、**ゲームシステムを順番に覚え、景観が変わり、探索の密度が上がっていくステージ列**として設計します。

実装追跡は [#262](https://github.com/tomiya7688/kadoka_quest/issues/262) を親Issueとします。

## 目的

開発者と実装AIが、新しいマップを追加するときに次を共通認識として持てるようにします。

- 各ステージの役割
- ワールド内の接続位置
- 主要ランドマーク
- 景観とObjectの方向性
- 主導線と脇道
- 想定する戦闘・探索密度
- 次のステージへ進む理由
- 既存機能のどれを使うか
- 将来の実装順

本書はステージの**設計正本**です。実際の座標・JSON契約は `data/maps/<id>/map.json` と [FORMATS.md](../FORMATS.md) を正本とします。

## Kadoka Questらしいステージの雰囲気

ステージを増やすときは、「RPGだから森・洞窟・火山を順番に置く」だけにはしません。

Kadoka Questでは、次の空気感を優先します。

### のんびりしている

危険地域以外では、常に敵やイベントを詰め込みません。

- 何も起きないベンチ
- 水の音がする場所
- 花がまとまって咲いている場所
- 一本道の途中にある大きな木
- 立ち止まって景色を見る高台

のように、「そこにいるだけ」の場所も作ります。

### 少し変

怖い、壮大、格好いいだけでなく、少し首をかしげるものを置きます。

- なぜか片方だけ落ちている靴
- 誰が置いたか分からない箱
- まるが動かしたようなガラクタ
- 変な位置の看板
- 使い道が分からない古い道具
- 調べても大したことを言わない物

大きな報酬がなくても、見つけたこと自体が小ネタになります。

### 生活感がある

街や安全地帯は、機能だけを置いたメニュー空間にしません。

- 木箱
- 樽
- 籠
- 果物
- 水桶
- ベンチ
- 作業小屋
- 洗濯物や荷物に相当するObject

等を使い、人やモンスターがそこで生活しているように見せます。

### おばけは怖すぎない

まる/かどかを中心とするおばけの地域は、ホラーへ寄せすぎません。

暗い色、水音、墓石、夜道等は使えますが、

- 白い花
- 小さな灯り
- 静かな会話
- 拾い物
- のんびり歩くおばけ

を混ぜ、「怖い場所」より「夜の静かな場所」にします。

### 戦闘しない場所にも価値を持たせる

全ステージを戦闘エリアにしません。

果樹園、風見の丘、おばけの住処等は、

- 会話
- 景観
- 小ネタ
- アイテム
- shortcut
- 次地域の予告

を報酬にできます。

### 小さな反応を大事にする

大規模イベントだけでなく、プレイヤーの行動へキャラクターや世界が小さく反応することを重視します。

例:

- まるの目の前でりんごを使う
- かどかの目の前でみかんを使う
- MODで変な状態を作ると専用台詞が出る
- 特定の仲間を連れて変な物を調べると一言変わる

こうした反応は本編攻略に必須にせず、見つけた人が少し嬉しい程度にします。

## ステージ設計の基本原則

### 1. 1ステージ1役割

各ステージには「ここで何を覚える/試す場所か」を1文で説明できる主役を持たせます。

例:

- はじまりの街: 安全地帯と拠点機能を理解する
- はじまりの森: 野生戦闘に慣れる
- 新緑の森: 一本道から外れて探索する
- メタル渓谷: 高リスク地域へ自分で踏み込む

1マップへ新機能を何種類も同時に初登場させません。

### 2. 主道は迷わせず、脇道で迷わせる

本編の主ルートは、初見でも景観から進行方向を推測できるようにします。

主街道は原則として3マス幅を基準とし、以下のいずれかで進行方向を示します。

- 道
- 柵
- 水路
- 崖
- 街灯
- 看板
- 建物の向き
- Objectの並び

探索要素は主道から外した脇道へ置きます。脇道は次のどちらかを満たしてください。

- 本線へ再接続する
- 行き止まりに明確な報酬/イベント/ランドマークがある

何もない長い行き止まりは作りません。

### 3. 1〜2画面ごとに視覚的な目印を置く

単色blockだけが長く続く地域を避けます。

[#215](https://github.com/tomiya7688/kadoka_quest/issues/215) のObject layerを使い、各地域へ次のようなランドマークを置きます。

- 大木
- 岩山
- 井戸
- 石像
- 水場
- 橋
- 崩れた柱
- 墓石
- 荷物
- 看板
- 街灯

Objectは見た目だけです。通行可否・敵出現可否等のゲームルールは下のblockが正本です。

### 4. 安全地域と危険地域を見た目でも区別する

村・牧場・住処等は、野生出現の有無だけでなく色、Object密度、道幅、BGM等でも「安全そう」に見えるようにします。

危険地域では逆に、道が細くなる、岩が増える、明かりが減る等の変化を付けます。

### 5. 秘密は完全なノーヒントにしない

隠し入口は、少なくとも次のいずれかを置きます。

- 張り紙
- 不自然なObject
- 行き止まりに見えるが少し開けた地形
- NPCの会話
- 色の違う地形
- 特定アイテム/スキルのヒント

新緑の森→おばけの住処のような秘密ルートは、見逃しても本編進行不能にならない構造を基本とします。

### 6. ステージ固有コードを増やさない

ステージ固有挙動は、可能な限り次の既存契約を組み合わせて実現します。

- transition
- message
- church
- fixed mob
- conditional dialogue
- item/skill use gimmick
- spawn table
- encounter context
- object placement

`if map_id == ...` のような専用コードを増やさないでください。

## 現行ステージの完成イメージ

### はじまりの街

**役割:** 安全な拠点として、教会・牧場・東口の3要素だけを迷わず理解させます。

**景観:** 石畳、低い柵、街灯、荷物、井戸、小さな植栽。中央を広く取り、森よりObject密度を上げます。

**ランドマーク:** 教会、牧場入口、東門。

```text
┌────────────────────────┐
│          [教会]         │
│             │           │
│ [牧場] ── [中央広場] ── 東門 ─▶ 森
│             │           │
│          開始地点       │
└────────────────────────┘
```

**改善点:**
- 教会前は白/明色Objectで遠目から識別できるようにします。
- 牧場側は柵・藁・木箱等で生活感を出します。
- 東門は街道Object/看板を集中させ、出口と分かるようにします。

### モンスター牧場

**役割:** 戦闘の外で「仲間は管理できる」ことを教えます。

**景観:** 柵、牧草、餌箱、樽、台帳机。広場よりも目的物を中央奥へ集めます。

```text
┌──────────────────────┐
│        [牧場台帳]      │
│            ▲          │
│  柵      管理エリア     │
│                        │
│        入り口           │
└──────────┬───────────┘
           ▼
       はじまりの街
```

台帳までの導線上へ不要なイベントを置かず、管理画面へ迷わず到達できるようにします。

### はじまりの森

**役割:** 野生敵との接触、戦闘、回復/帰還を覚える最初の危険地域です。

**景観:** 明るい草地、小さい木、花、細い水場。深い森Objectは画面端へ寄せ、圧迫感を出しすぎません。

```text
街 ◀═══ 主街道 ═══╦══════▶ 新緑の森
                  ║
             小さな脇道
                  ║
               [果樹]
```

**設計:**
- 主街道から大きく外れなくても戦闘が発生します。
- 初期敵は見た目/能力とも分かりやすい種族を中心にします。
- 初回の寄り道報酬として果樹等を置き、探索する意味を軽く教えます。

### 新緑の森

**役割:** 「道から外れて調べる」探索を初めて要求します。

**景観:** はじまりの森より木・岩・水場を増やします。主街道は維持しつつ、南側だけ密度を上げます。

```text
はじまりの森 ◀══════ 主街道 ══════▶ ロクター村
                          │
                          │ 南の脇道
                          ▼
                     [張り紙]
                          │
                      [怪しい岩]
                          │
                          ▼
                     おばけの住処
```

南側の秘密入口は、主街道から見れば「何かありそう」だが、行かなくてもロクター村へ進める配置を維持します。

### おばけの住処

**役割:** 戦闘ではなくキャラクターとの生活感・会話・小ネタを楽しむ秘密拠点です。

**景観:** 暗い青系、湧き水、ガラクタ、拾い物、石、袋、木箱。整った村ではなく、まるが勝手に物を動かしたような少し散らかった配置にします。

```text
入口 ───── 生活スペース ─────┐
             ○ まる             │
                               │
          ガラクタ      水路     │
             □                 │
                    かどか ○    │
                               │
                 [水の湧き場]   │
                 合言葉入力     │
└──────────────────────────────┘
```

**重要な体験:**
- まる/かどかが歩き回ります。
- プレイヤーと対面中は対象が移動せず、アイテム欄を開いても待ちます。
- まるへりんご、かどかへみかんを使うと本人が受け取ります。
- MOD等で複数かどかを作った場合の隠し反応もここへ集約します。

### ロクター村

**役割:** 序盤を終えて中盤へ移る第2拠点です。

**景観:** はじまりの街より小さく、川/水場と石造りを強めます。西から到着し、北に教会、東に次の山道が見える構造にします。

```text
新緑の森 ◀── 西門 ── [村広場] ── 東門 ─▶ 山道
                         │
                         ▼
                       [教会]
                 水場 / 小さな橋
```

現行では東側遷移がありません。景観上は先に「この先がある」と分かる東門/道を作り、実装時に [#264](https://github.com/tomiya7688/kadoka_quest/issues/264) へ接続します。

## 新規ステージ設計

### こもれび果樹園（仮）

Issue: [#270](https://github.com/tomiya7688/kadoka_quest/issues/270)

**役割:** 果物と生活感を世界の中へ置く、戦闘から離れた小さな寄り道です。

**接続:** ロクター村から出入りし、果樹園内を1周すると村側へ戻れる回遊型にします。

**景観:** りんご・みかん・なし・柿の木、籠、木箱、水桶、ベンチ、小さな作業小屋。整いすぎた農業施設ではなく、手入れされた田舎の果樹園程度にします。

```text
ロクター村
    │
    ▼
 [入口の小屋]───[りんごの列]
      │               │
 [水桶/ベンチ]    [みかんの列]
      │               │
 [なし/柿の木]───────┘
      │
      └──────────▶ 村へ戻る
```

**Kadoka Questらしさ:**
- りんご/みかんが単なるinventory IDではなく、実際に木になっています。
- まるやかどかへ渡す果物を「ここで見たもの」として覚えられます。
- 戦わなくても寄る理由がある場所にします。
- 果物取得は回数/再取得条件を明示し、無限稼ぎにはしません。

### 忘れもの原っぱ（仮）

Issue: [#272](https://github.com/tomiya7688/kadoka_quest/issues/272)

**役割:** なぜか色々な物が落ちている、少し変で、でも怖くない草原です。

**接続:** 新緑の森の脇道から入り、月あかりの古道へ繋がる別経路を持たせます。

**景観:** 片方だけの靴、古い箱、袋、縄、壊れた看板、空き瓶のような「何でここにあるのか分からないもの」。すべてを拾えるアイテムにはせず、大半はObjectとして置きます。

```text
新緑の森
    │
    ▼
┌──────────────────┐
│ 箱        袋       │
│      まがった道    │
│ 靴            縄   │
│        [変な物]    │
└─────────┬────────┘
          ▼
   月あかりの古道
```

**Kadoka Questらしさ:**
- まるが「これひろった」と言う背景を世界側で補強します。
- まる/かどかがパーティにいる時だけ変わる小さな反応を置けます。
- 高価な報酬より「何だこれ」を優先します。
- ガラクタを全部interactiveにせず、見た目だけの変な物を多くします。

### 月あかりの古道（仮）

Issue: [#274](https://github.com/tomiya7688/kadoka_quest/issues/274)

**役割:** おばけらしいがホラーには寄せすぎない、静かな夜の裏道です。

**接続:** おばけの住処側から条件付きで見つかり、忘れもの原っぱへ抜けます。これにより、おばけの住処を完全な袋小路にしません。

**景観:** 青黒い地面、白い花、小さな灯り、古い石柱、少数の墓石、遠くから続く水音。怖さより「静か」を優先します。

```text
おばけの住処
      │
   [隠し出口]
      │
  白い花の道
      │
 [月の丸い広場]
      │
 小さな灯りと石柱
      │
      ▼
忘れもの原っぱ
```

**Kadoka Questらしさ:**
- まる/かどかが普段どこを歩いていそうか想像できる場所にします。
- ghost系の敵を出す場合も極低密度にし、散歩感を壊しません。
- 開通条件はplain flag/eventで持ち、専用コードへしません。

### 風見の丘（仮）

Issue: [#271](https://github.com/tomiya7688/kadoka_quest/issues/271)

**役割:** 中盤で戦わずに立ち止まる、安全な眺望地点です。

**接続:** ロクター山道の短い脇道。行き止まりですが、景色そのものを報酬にします。

**景観:** 大きな一本木、風見標または古い風車、花、ベンチ、遠くを指す看板。

```text
ロクター山道
      │
      └── 脇道
            │
        [一本木]
            │
     [風見標 / 風車]
            │
        景色の端
```

**Kadoka Questらしさ:**
- 「何も倒さなくても来てよかった」場所を作ります。
- 次のメタル渓谷や遺跡を、看板や遠景の表現で予告します。
- イベントを詰め込まず、1〜2個の会話/調べる反応だけにします。

### 雨だまり湿地（仮）

Issue: [#273](https://github.com/tomiya7688/kadoka_quest/issues/273)

**役割:** 森・山・石造遺跡の間に、明るい水辺の色を挟む寄り道です。

**接続:** 古い水路遺跡の途中から入り、別区画へ戻る小さなloopとして扱います。

**景観:** 浅い水、小島、葦、丸太、木道、雨だまり。沼地の不気味さではなく、雨上がりの青緑を基調にします。

```text
水路遺跡A
   │
   ▼
[木道]──[小島]──[丸太]
   │        │       │
[水草]   [雨だまり] │
   └────────┴───────┘
            │
            ▼
       水路遺跡B
```

**Kadoka Questらしさ:**
- 一本道を広げるのではなく、数分だけ寄れる小さな自然ステージにします。
- 水場のObjectを使い、歩ける場所を見た目で判断できます。
- 行き止まりには花、拾い物、短い会話等の小さな意味を持たせます。

### ロクター山道（仮）

Issue: [#264](https://github.com/tomiya7688/kadoka_quest/issues/264)

**役割:** 森の広いフィールドから、狭い中盤ルートへプレイ感を変えます。

**想定Lv:** 9〜14程度を初期目安とします。実際の値はバランス評価で調整します。

**景観:** 崖、岩、倒木、草の少ない地面、古い標識。道は折返し、上下差があるように見せます。

```text
ロクター村
    │
    ▼
┌──────────── 崖 ────────────┐
│  ═══════╗                  │
│         ║   [休憩所]       │
│   脇道 ═╝      │           │
│   [宝/イベント]│           │
│                ╚══════╗    │
│                    [岩門]  │
└───────────────────────╬────┘
                        ▼
                   メタル地域
```

**システム:**
- 固定モブ/旅人
- [#46](https://github.com/tomiya7688/kadoka_quest/issues/46) の地点ギミックを1つ以上
- 短い脇道
- 岩/倒木Object
- 新緑の森より一段高い敵Lv

山道そのものを迷路にはしません。見通しの悪さではなく、地形の圧迫感で中盤感を出します。

### メタル渓谷（仮）

Issue: [#265](https://github.com/tomiya7688/kadoka_quest/issues/265)

**役割:** 「危険だが入る価値がある」高リスク地域を作ります。

**景観:** 灰色の岩、金属片、暗い水、崩れた採掘跡、光る鉱石Object。

```text
                 ┌── 安全な通過路 ─────▶ 次地域
山道 ── 分岐 ───┤
                 └── 危険区域
                       │
                   金属の岩場
                       │
                 メタルスライム
                       │
                   帰還shortcut
```

**システム:**
- `encounter_context: metal_area` 相当
- パーティに応じた動的Lv
- メタルスライム
- 逃走判断
- MP/回復資源管理

本編の一本道をメタル区域へ強制しません。安全な通過路を残し、危険区域へ踏み込むかはプレイヤーが選びます。

### 古い水路遺跡（仮）

Issue: [#266](https://github.com/tomiya7688/kadoka_quest/issues/266)

**役割:** 初めての明確なダンジョンとして、ループ構造と地点ギミックを使います。

**想定Lv:** 15〜22程度を初期目安とします。

**景観:** 石床、水路、橋、壊れた柱、石像、瓦礫、暗い水。

```text
入口
 │
 ▼
[中央水路]══════[北区画]
 │    ▲             │
 │    │shortcut     │
 ▼    │             ▼
[西区画]───────[東区画]
 │                  │
 └────[水門ギミック]┘
          │
          ▼
         出口
```

**設計:**
- 水路を見れば現在位置を推測できるようにします。
- 最低1つ、解放すると入口付近へ戻れるshortcutを作ります。
- 地点アイテム/スキル利用を1つ以上使います。
- dungeon Objectを積極的に使います。
- 状態異常・属性を意識する敵を配置し、単純な攻撃連打以外の判断を要求します。

### 境界の遺跡（仮）

Issue: [#267](https://github.com/tomiya7688/kadoka_quest/issues/267)

**役割:** 本編で学んだ仕組みをまとめて使う終盤ステージです。

**想定Lv:** 22〜30程度を初期目安とします。本編をLv100前提にはしません。

**景観:** 屋外遺跡→内部→最奥の順に、少しずつObject密度と暗さを上げます。

```text
[安全な入口 / 復活地点]
          │
          ▼
      外周遺跡
       ╱     ╲
   左ルート  右ルート
       ╲     ╱
       中央門
          │
       最奥区画
          │
      [本編最終イベント]
          │
     story_complete=true
```

最終ボスの名称・物語上の正体は本書では固定しません。

重要なのは、`story_complete` を「終盤ステージへ入った」だけで立てず、**本編完了イベントを正常に終えた時だけ設定すること**です。

クリア済みデータで同イベントを再訪しても、報酬やフラグが壊れない冪等な契約にします。

### サイコロ回廊（仮）

Issue: [#268](https://github.com/tomiya7688/kadoka_quest/issues/268)

**役割:** 本編後の編成・AI・対応力を試す挑戦地域です。

`dice_slime` が「物語クリア後の再獲得用定義」であることを、実際のゲーム導線へ接続します。

**景観:** 規則的な四角い床、数字/目を連想するObject、左右対称だが一部だけ崩れた構造。

```text
          story_complete
                │
                ▼
             [入口]
             ╱    ╲
         Route A  Route B
            │       │
            └───┬───┘
                ▼
        [サイコロスライム]
                │
          再獲得 / 挑戦
```

ランダム性は戦闘の特徴として使います。ナビゲーションまで完全ランダムにして、運が悪いと進めない構造にはしません。

## ステージごとの見た目ルール

### 街・村

- 道幅: 3マス以上を基本
- Object: 看板、井戸、街灯、木箱、樽、ベンチ、植栽
- 敵出現: なし
- 入口/出口: 門、道、看板で明示
- 重要施設: 周囲よりObject密度や床材を変える

### 森

- Object: 木、若木、切り株、倒木、花、岩、きのこ
- 主道: path blockを連続させる
- 脇道: grass中心でもよいが、入口へ目印を置く
- 画面全体を木Objectで埋めず、歩ける余白を残す

### 山・渓谷

- Object: 岩、岩塊、倒木、崩れた標識
- block: wall/非通行地形で自然な幅を作る
- 一本道でも折返しを使って距離感を出す
- 危険区域は色/岩密度を変える

### 遺跡・ダンジョン

- Object: 柱、石像、瓦礫、骨、墓石、壁片
- 水/壁等の長い線をランドマークとして使う
- shortcutは開通前後をイベント/flagで表現する
- 行き止まりには必ず意味を持たせる

## Map IDとdisplay name

新規マップは、display nameと内部IDを分けます。

例:

```text
map id: rokuta_pass
display name: ロクター山道
```

仮称段階で実装を開始する場合でも、内部IDを後から何度も変更するとtransition/save/E2Eへ影響します。

そのため、実装Issue着手時に内部IDだけは先に確定してください。

## ステージ実装時のDeveloper手順

新しいステージを追加する開発者は、次の順に進めてください。

1. 本書へステージの役割・接続先・簡易図を追加または確認してください。
2. Map EditorまたはDeveloper CLIでmapを作成してください。
3. 主道とblockによる通行ルールを先に完成させてください。
4. transitionを設定し、往復可能であることを確認してください。
5. spawn table / fixed mob / eventを追加してください。
6. [#215](https://github.com/tomiya7688/kadoka_quest/issues/215) のObjectを追加し、景観を整えてください。
7. Project Validationを実行してください。
8. Player Previewで入口→目的地→出口を実際に歩いてください。
9. [E2E期待動作](../testing/E2E_EXPECTATIONS.md)へ主要導線を追加してください。
10. save/reloadを跨いでもtransition/flagが維持されることを確認してください。

主道を完成させる前に装飾を大量配置しないでください。地形・通行・接続が正しいことを先に確認します。

## ステージ完成チェック

### 進行

- [ ] 入口が分かる
- [ ] 本編の出口が分かる
- [ ] 往復可能
- [ ] 進行不能マスがない
- [ ] save/reloadで位置とflagが壊れない

### 景観

- [ ] ステージの色/地形テーマを1文で説明できる
- [ ] 1〜2画面ごとにランドマークがある
- [ ] 主道がObjectで隠れない
- [ ] 大きな空白を単色blockだけで埋めていない
- [ ] Objectへcollision等のゲームルールを持たせていない

### 戦闘

- [ ] 前地域より難易度が急上昇しすぎない
- [ ] 出現種族とLv帯に理由がある
- [ ] 安全地域では敵が出ない
- [ ] 特殊地域ではencounter contextが明示される

### イベント

- [ ] 必須イベントを見落としても進行不能にならない、または十分な誘導がある
- [ ] 隠し要素は本編必須条件にしない
- [ ] one-shot flagの再実行条件が定義されている
- [ ] map固有コードではなくデータ契約を優先している
