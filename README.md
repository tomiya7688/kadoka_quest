# kadoka quest

`kadoka quest` は、Python と pygame-ce で作る、2Dオープンワールド型のモンスターRPG初期版です。

ゲームルール、pygame描画、JSONデータは分離しています。フィールドの移動・通行・イベント検索はpygame非依存の `core/field_engine.py`、フィールド描画は `ui/field_renderer.py`、入力・保存・画面遷移の仲介は `apps/game.py` が担当します。将来のGDScript版／Lua版では、既存JSONと処理層の入出力契約を維持したまま画面層を置き換えられます。詳細は [移植境界機能説明書](docs/移植境界機能説明書.md) を参照してください。

画像・ブロック・マップ・種族・Lv別能力・習得スキル・＋選択・装備・個体AI・保存パーティを、暗号化しないJSONとフォルダで管理します。エディタ専用形式やエクスポート工程はありません。エディタが保存したファイルをゲーム本体がそのまま読みます。

## 現在できること

- ランチャーからゲーム本体、各エディタ、個体管理、開発用データクリエイターを起動
- ランチャーで名前付きセーブデータを新規作成・別名保存・読み込み
- スクロールする2Dフィールドを上下左右に探索
- 通行判定はマス単位のまま、主人公・固定モブ・追従カメラを滑らかに表示
- ブロックごとに「自機通行」「敵出現」「敵通行」「色または画像パス」を独立設定
- 敵の姿は表示せず、マップ裏で歩く野生モンスターと接触したときに遭遇
- 「戦う」では個別命令を出さず、各個体のAIと行動指針で全員が自動行動
- 戦闘はキーボードだけでも操作でき、Aキーでオート戦闘を切替可能
- 主人公を含め4枠。主人公を外した編成も可能
- 個体ごとの名前、Lv、経験値、＋選択、装備、AIをフォルダ保存
- モンスター所有数と保存パーティ数は無制限（実際の上限はストレージ容量）
- AIだけを初期化し、名前・Lv・＋・装備は保持
- 個体AIは自分のHP、味方の損耗、MP、人数差、敵の残HP、敵とのレベル差を軽量な状況タグとして学習
- 保存パーティは個体IDだけを参照し、消えた個体IDは空き枠として読込
- 外部個体フォルダの通常獲得用再走査
- 外部個体との模擬戦。模擬戦中は双方のAIを更新しない
- `まる / かどか` の合言葉再獲得と、フィールドでの「ものを拾う」
- 全滅時はその場ではなく、最後に登録した教会から復活
- はじまりの街、街のモンスター牧場、始まりの森、新緑の森、第二の村ロクター村、おばけの住処を相互移動
- 全8種族に戦闘立ち絵と前後左右のドット絵を収録。5種類とも原寸PNGは64×64で、ゲームでは輪郭をぼかさず拡大

これは完成版ストーリーではなく、データ形式と主要ループを実際に試せる土台です。条件分岐する会話、ボス復活、クラフト、＋選択UIなどは次の実装範囲です。

## セットアップ（Windows）

1. このフォルダでターミナルを開きます。
2. 仮想環境を作ります。

   ```powershell
   py -m venv .venv
   ```

3. pygame-ce を入れます。

   ```powershell
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

4. `run_kadoka_quest.bat` をダブルクリックします。ターミナルからなら次でも起動できます。

   ```powershell
   .venv\Scripts\python.exe launcher.py
   ```

## 遊び方

1. ランチャーで「ゲームを開始」を押します。初回は主人公とボールスライムの個体フォルダが自動作成されます。
   セーブ名を入力して「新規作成」、現在のデータを複製する場合は「別名保存」、続きから遊ぶ場合は一覧で選んで「選択データを読み込む」を押します。
2. 新しい冒険は「はじまりの街」から始まります。街の東口から始まりの森へ進めます。
3. 街の西側にあるモンスター牧場では、奥の牧場台帳を `Space` で調べると個体・AI・パーティ・編成プリセットを管理できます。台帳を閉じると変更内容がゲームへ反映されます。
4. `矢印キー` または `WASD` で移動します。野生モンスターの姿は見えませんが、敵も裏で1マスずつ歩き、同じマスで衝突すると戦闘が始まります。
5. 戦闘では `←/→` でコマンド選択、`Enter` で決定します。`1`〜`4` は「戦う・スカウト・道具・逃げる」の直接実行、`A` はオート戦闘の開始・停止です。モンスター1体ずつの技は指定せず、全員が自分のAIで行動します。
6. 新緑の森の南側の脇道には張り紙と岩があります。岩は通り抜けられません。岩の隣で `Space` を押すと、隠された入口からおばけの住処へ入ります。
7. 住処の右上にある水の湧き場を `Space` で調べると、7文字の仮想キーボードが開きます。`へいわなすみか` と入力して「決定」を押すと、所有していない `まる / かどか` がLv1で牧場に加わります。
8. `まる / かどか` は仲間にしたかどうかに関係なく、おばけの住処を歩き回ります。探索画面では専用スプライト、戦闘画面では提供された立ち絵を表示します。
9. 住処では、まるは1回の移動機会に最大2歩動き、かどかは時々ゆっくり動くため、まるの方が活発です。
10. `1`〜`4` で右側の個体を選び、`T` で行動指針、`R` でその個体のAIだけを初期化します。
11. まるかかどかをパーティへ入れて `L` を押すと「ものを拾う」を使えます。
12. 始まりの森を東へ抜けると新緑の森、その東に第二の村ロクター村があります。村の教会を調べると、以後の全滅時はロクター教会から復活します。
13. 街道と主要通路は3マス幅を基本にしています。看板・張り紙・岩・牧場台帳は通り抜けられないため、隣から `Space` で調べます。

### モンスターの見た目編集

モンスターエディタで種族を選び、「見た目編集」を押すと、次の5種類を同時にプレビューできます。

- 戦闘画面の立ち絵
- フィールドの正面、右向き、左向き、後ろ向き

上部のプレビューを選ぶと64×64のドット絵編集画面へ切り替わります。左クリックで描画、右クリックで透明化し、「5種類を保存」でPNGと種族JSONへ直接反映します。`－`・`＋`・`等倍`ボタン、またはキャンバス上のマウスホイールで表示を50%～400%に拡大・縮小できます。

パレット下の入力欄へ `#RRGGBB` を入力して「色を追加」を押すとペン色を追加できます。登録済みの色を追加した場合は、その色が選択されます。「選択色を削除」で現在の色をパレットから外せます。透明色と最後の不透明色は削除できず、パレットは最大16色です。このパレット操作はモンスターとブロックの両エディタで共通です。

「塗りつぶし」はクリックしたピクセルと同色でつながった領域だけを、輪郭を越えずに着色します。下部の画像パスへPNGなどの画像を指定して「画像読込」を押すと、縦横比を維持したまま64×64内へ最近傍法で縮小・中央配置します。小さい画像は拡大しません。色差は0～255で指定でき、読込後または「色統合」時に近いRGB色をまとめます。塗りつぶし、画像読込、色統合はそれぞれ `Ctrl+Z` で戻せます。

収録画像は `assets/characters/種族ID/` にあり、`portrait.png` と `field_front/right/left/back.png` をそのまま差し替えられます。素材はすべて64×64キャンバスに統一し、表示時は最近傍法で拡大するため、ドットの輪郭がぼやけません。まる・かどかの戦闘立ち絵は提供された元画像を64×64へ縮小したものです。

### データ交換のキー

- `F5`: `imports/acquire/` を再走査し、まだ所有していない個体IDを通常の仲間として獲得
- `F6`: `imports/simulation/` の個体と模擬戦（AI更新なし）
- `F7`: 現在編成を新しいパーティファイルとして保存
- `F8`: 保存パーティを順番に読込。存在しない個体IDは空き枠

すぐ模擬戦を試す場合は、`examples/simulation_party/guest_dice_slime/` フォルダを `imports/simulation/` の中へコピーしてから `F6` を押します。

## エディタ

### ブロックエディタ

`block_editor.py` は `data/blocks/*.json` を直接編集します。自機通行、敵出現、敵通行は別々の真偽値です。見た目は `#RRGGBB` の色、または `assets/` からの相対パスにできます。「ドット絵編集」ではモンスターエディタと同じ共通ドットエディターへブロック画像だけを渡し、64×64 PNGを編集します。拡大・縮小、パレット編集、塗りつぶし、画像読込、色統合も同じ操作です。

### マップエディタ

`map_editor.py` は `data/maps/*/map.json` を直接編集します。

- 左クリック: 選択ブロックを配置
- 矢印キー: 表示位置をスクロール
- `PageUp / PageDown`: 編集するマップを切替
- 生息モンスターを選んで「出現追加 / 出現削除」
- 種族を選んで「固定モブ配置」。村人・ボス・固定モンスターを地形へ重ねて配置
- 固定モブごとに会話デッキ、会話/戦闘、停止・ランダム・追跡AI、戦闘レベル、移動間隔、移動頻度、会話/勝利後に消えるか、再訪時に復活するかを設定
- 「プリセット」から現在のマップを再利用可能なJSONとして保存
- プリセットを現在のマップへ適用、または別IDの新規マップとして作成
- `Ctrl+S`: 保存

黄色い小印はイベント位置です。イベント本文、重み、出現Lv、条件フラグなど細かい値はJSONで編集できます。

### モンスターエディタ

種族一覧の一番上にある「＋ 新規作成」から、既存種族をコピーせずに新しいモンスター種族を作れます。種族ID、名前、色、レベル別能力、AI、習得スキルを編集して保存すると、公開形式の4 JSONと透明背景の64×64プレースホルダー画像5枚が生成されます。作成後は通常の見た目編集で各画像を描き直せます。詳しくは [モンスター種族新規作成機能説明書](docs/モンスター種族新規作成機能説明書.md) を参照してください。

`monster_editor.py` は選択した種族の次のファイルを直接編集します。種族IDを書き換えて保存すると、現在の種族を土台に4ファイルを持つ新種族を追加できます。

- `species.json`: 名前、色、耐性、通常/特殊AI
- `stats.json`: Lv1〜100の6能力
- `skills.json`: レベルごとの習得スキル

＋1〜＋10の分岐は、種族ごとの `plus.json` に独立してあります。新種族は一覧先頭の「＋ 新規作成」から追加でき、保存直後から一覧へ表示されます。

### データクリエイター

`data_creator.py` は開発用のモンスター個体を作成します。種族・レベル・個体名・任意の個体IDを指定すると、レベル時点の能力と習得スキルを確認してから生成できます。

生成先は、現在のセーブへ直接追加、`imports/acquire` へ獲得用として保存、`imports/simulation` へ模擬戦用として保存、の3種類です。すべて通常個体と同じ公開JSON形式を使います。

## サンプル種族

- `slime`: 安定した標準型
- `ball_slime`: 低めの能力、非常に素早く器用、最初から再獲得可能
- `metal_slime`: 高防御・低HP、雷以外の魔法に強い、流体防御とメタルバースト
- `ghost`: 低防御・光弱点、見えなくなる、光を避ける、とりつく
- `maru`: 高めのHP/MP、低い戦闘力、変な物を拾う、特殊な抜けたAI
- `kadoka`: 高めのHP/MP、低い戦闘力、みかんと柿を拾う
- `dice_slime`: 高水準・高ランダム性、物語クリア後の再獲得用定義
- `hero`: 高めの平均能力、メンタル系無効、全体攻撃なし

ボールスライムは初期獲得専用で、どのマップの敵出現表にも入りません。マップエディタから追加しようとしても拒否されます。

## データの考え方

```text
data/species/ghost/       種族共通の公開データ
  species.json
  stats.json              Lv1〜100を明示
  skills.json
  plus.json

savedata/セーブデータ名/
  state.json             現在地、復活地点、現在パーティ、進行フラグ
  meta.json              セーブ名と作成日時
  items/items.json       所持アイテム

savedata/セーブデータ名/monsters/monster_xxx/  個体固有データ
  monster.json            種族ID、名前、Lv、＋選択、装備
  ai.json                 その個体だけのAI経験

savedata/セーブデータ名/parties/
  *.json                  個体IDを最大4枠参照
```

種族の能力値を直すと、その種族の既存個体にも反映されます。個体フォルダに最終ステータスを重複保存しないためです。詳しい形式は [docs/FORMATS.md](docs/FORMATS.md) を参照してください。

## 検証

### 実行時アプリ間コマンド

ゲーム本体のpygame入力は、フィールド・戦闘・暗号入力の処理を直接呼びません。入力を `target / action / payload` からなるコマンドへ変換し、共通バスが対象アプリ1つへ配送します。コマンドアプリはpygameに依存せず、方向はキーコードではなく `left / right / back / front` で受け取ります。

ロジック整理は第5段階まで完了しています。`RuntimeOrchestrator` が画面モードと共通コマンドバスを所有し、フィールド効果を `field / battle / password / manager` の意味コマンドへ変換します。pygameループとフィールド処理は別画面のメソッドを直接呼びません。詳細は [コマンド駆動アプリ基盤機能説明書](docs/コマンド駆動アプリ基盤機能説明書.md)、[戦闘責務分離機能説明書](docs/戦闘責務分離機能説明書.md)、[フィールドアクター責務分離機能説明書](docs/フィールドアクター責務分離機能説明書.md)、[フィールドセッション責務分離機能説明書](docs/フィールドセッション責務分離機能説明書.md)、[実行時オーケストレーター機能説明書](docs/実行時オーケストレーター機能説明書.md) を参照してください。

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

テストは、7種のサンプル、Lv1〜100、10段階の＋定義、ブロック/マップ参照、個体再走査、欠損IDの空き枠化、AIリセット、AI自動戦闘、模擬戦でAIが変化しないこと、各画面のヘッドレス起動を確認します。

## MOD方針

JSONはUTF-8の平文で、署名・暗号化・アンチチートを置いていません。バックアップ、改造個体、独自種族、独自マップをそのまま扱う前提です。壊れたJSONや未知の種族IDは読み飛ばしますが、正規データと改造データを区別して制限する仕組みはありません。
